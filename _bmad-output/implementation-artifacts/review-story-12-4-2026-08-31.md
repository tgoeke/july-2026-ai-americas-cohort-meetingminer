## Scope

Adversarial full-spec review of Story 12.4. Priority targets are the in-store
AD-18 authorship/review marking, the prohibition on documents becoming citation
targets, the unchunked one-record-per-source decision under real corpus limits,
the reusable ungated-row declaration and state vocabulary, all document
projection settle points, and prompt assembly including first-block-only
document context.

The reviewer will record each confirmed finding here before remediation and
will preserve red-first evidence for every patchable finding.

## Findings

### F-01 — The public document projection writer accepts unguarded records (high, patchable)

`projections.search.project_documents()` accepts arbitrary mappings and writes
them straight to the `documents` index through `_add()`. The only AD-18 and
AD-6 guards live in `documents.document_record()`, so a direct projection call
can persist a document with no `reviewState` / `authorship` / `reviewLabel`, or
one carrying `citable: true` / `momentId`. This defeats both code-enforced
constraints at the store boundary even though the two current production
callers happen to build their records correctly first.

Remediation: make the public writer validate every supplied record before the
first Meilisearch operation, and add red-first tests proving that an unlabelled
record and a citation-shaped record are refused without touching the client.

Red-first evidence: the focused module produced `2 failed, 39 passed`; both
new cases reached `_add()` and failed later with `ProjectionError`. After the
writer repeated both guards, the module produced `41 passed`, focused Ruff was
clean, and focused mypy reported no issues.

### F-02 — The new settle-point trigger escapes the worker-test isolation fixture (high, patchable)

The autouse `_no_incidental_projection` fixture stubs only
`runner._maybe_project`. Story 12.4 added the independently named
`runner._maybe_project_documents`, and every ordinary worker test that settles
`extract` therefore executes the real Meilisearch projection. Its exceptions
are swallowed by design, so the fast suite can silently write retrieval state
when the store is up or appear green after an unintended failed store call.
There is also no runner-level test of the normal and resumed `extract` settle
paths; direct entrypoint tests stay green if either call site is removed.

Remediation: include the document trigger in the autouse isolation boundary,
provide an explicit fixture that restores it only for trigger tests, and add
red-first coverage for default isolation plus normal/resumed/failure/once-per-
pass behavior.

Red-first evidence: the default-isolation test failed because the real trigger
called `project_extraction_documents` and logged `projection.documents_done`.
After extending the fixture, the isolation test and the normal/resumed/failure
runner tests produced `3 passed`; focused Ruff was clean.

### F-03 — Meeting-level prompt folding launders document claims through an arbitrary moment (high, open owner/spec decision)

The document has no claim-to-moment anchors, yet `build_synthesis_prompt()`
places its complete analysis under whichever retrieved moment from the meeting
happens to come first. A synthesis can repeat a claim found only in that
document, append that unrelated moment's valid marker, and pass the code gate.
Likewise, instructions or valid moment markers embedded in adopted/generated
document text are placed directly in the prompt; the validator proves only
that the output marker names a retrieved live moment, not that the transcript
supports the document-derived sentence. This is a sixth citation path in
substance: the document is not the wire target, but it supplies the claim while
an arbitrary moment supplies its evidence costume.

The frozen story simultaneously requires `/chat` to read documents and says
their individual claims reach answers only through moments they anchor to,
while the retained document schema carries no such anchors. A safe remediation
requires an owner choice: remove document text from synthesis, or add a
deterministic claim-to-moment relation before allowing it to ground answers.
Prompt wording or delimiter escaping alone cannot enforce the invariant.

### F-04 — Store readers accept and then launder contradictory review/citability fields (high, patchable)

The document writer and query parser require only a nonblank `reviewLabel`, so
`"Published — human approved"` passes beside `reviewState="unreviewed"`.
The query does not retrieve `citable`; the API then hardcodes `false`, making a
foreign record that actually says `citable: true` look safe. Tighten both
boundaries to the canonical label, retrieve and require literal false, and
refuse before a rendering surface sees the hit.

Red-first evidence: the focused module produced five failures covering the
contradictory builder label, the missing retrieval field, and contradictory or
missing read-side fields. After the guards were tightened it produced
`45 passed`; focused Ruff was clean.

### F-05 — First-block-only assignment happens before capacity selection (medium, patchable)

Documents are marked as assigned while candidates are built. Artifact-priority
capacity selection can later drop that first candidate but retain another
moment from the same meeting, leaving all selected blocks without the matching
document. Assign each meeting's context to its first *selected* block and keep
the document allowance inside the capacity calculation.

Red-first evidence: a forced-capacity test retained a later moment from the
meeting but found the document sentinel zero times. After selection-aware
assignment, that test plus the existing once-per-meeting and no-moment cases
produced `3 passed`; focused Ruff was clean.

### F-06 — The reusable review mechanism misstates approved/authorship semantics (medium, patchable)

`ReviewMarking.reviewed` is false for `approved` even though its own label says
a human accepted the content. The composer and generic guard also accept blank
or unknown `authorship`; for unreviewed/extracted states the composed sentence
still says machine-written, producing contradictory fields. Add `approved` to
the accepted-as-reviewed states and make authorship a closed, validated value
whose sentence cannot contradict it.

Red-first evidence: six focused failures proved `approved` was classified
false and unknown/blank or machine-contradicting authorship passed both the
composer and generic guard. The repaired module produced `49 passed`; focused
Ruff was clean.

### F-07 — Postgres re-resolution does not detect a stale or cross-scoped index hit (high, patchable)

Re-extraction preserves the row UUID and projection failure is nonfatal. The
query hit carries old snippet text while `_resolve_documents()` combines it
with current Postgres provenance without comparing the indexed digest. It also
does not compare the hit's `meetingId`/`corpus` with the row, so a corrupt hit
can escape a scoped query and be returned under different current metadata.
Carry `sha256` and `corpus` through the internal hit, compare both scope and
digest during resolution, and drop/log any mismatch.

### F-08 — Config validation permits filters every scoped query will fail on (medium, patchable)

The loader requires only `kind` and `reviewState` as document filters, while
the query builder also emits `meetingId` and `corpus` filters. A config can
therefore pass startup and make every scoped request fail at Meilisearch.
Require all four fields at load.

### F-09 — The search UI loses document-index and stale-document state (medium, patchable)

The component never stores `documentsIndexMissing`; it therefore renders a
missing documents index as an ordinary zero. If the moments index is missing
while documents matched, it claims nothing was indexed even as it renders
documents. Finally, a failed follow-up document-only search preserves stale
documents but adds the stale warning only when moment rows exist. Preserve and
render the second index state, let live document matches override the global
empty claim, and key the stale warning on either result lane.

### F-10 — The Meilisearch-only settle point is withheld by Neo4j outage (high, patchable)

`project_extraction_documents()` enters `_open_stores()`, which always opens
and connectivity-checks Neo4j, even with `ensure=False` and even though this
path uses only `stores.client`. A healthy documents index therefore does not
receive a newly stored row when the unrelated graph store is down, contrary to
the “touches only the documents index” settle-point contract. Give this path a
Meilisearch-only opener under the same writer locks.

Red-first evidence: the settle-point test failed with the deliberately down
graph opener before reaching Meilisearch. After the path opened only the search
client, the real private-store test passed and focused Ruff was clean.

### F-11 — One exact unchunked record has a finite store ceiling (high, open owner/spec decision)

The story's long-document test is about 79 KB and never reaches Meilisearch.
The private stack's actual Meilisearch 1.53.1 binary reports
`--http-payload-size-limit` defaulting to `100000000` bytes, Compose supplies
no override, and `_add()` batches by record count rather than bytes. A valid
Postgres text above the request ceiling cannot be indexed as one exact record;
in delete-then-add flows it can also erase the prior projection before the
replacement fails. Keeping all three properties — arbitrary input length,
exact full text, and one unchunked record — is impossible under that finite
boundary. The owner must choose a retained-document size limit, a configured
store limit, explicit searchable-text truncation, or revised chunking/identity.
The shared main corpus was deliberately not queried while its owner rebuild
was running, so this review does not claim a largest-live-document measurement.

### F-12 — The 800-character chat budget is applied after unbounded reads and concatenation (medium, patchable)

`_DOCUMENT_CONTEXT` selects each complete `document_text`, the resolver holds
every result, and prompt assembly concatenates all complete documents for a
meeting before cropping to 800 characters. The model prompt is bounded, but
request memory and database transfer are not. Read at most the prompt budget
from Postgres in ranking order and assemble incrementally so arbitrarily large
documents cannot be materialized merely to discard their tail.

Red-first evidence: the bounded-read test failed because the SQL supplied no
limit parameter and attempted to return the whole source text. The repaired
read fetches only `budget + 1` characters per ranked row and assembly stops at
the combined allowance; it and both prompt-placement regressions produced
`3 passed`, with focused Ruff clean.
