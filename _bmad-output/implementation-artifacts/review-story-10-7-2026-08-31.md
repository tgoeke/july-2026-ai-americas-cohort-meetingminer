## Findings

### F1 — High — Synonymous topic rows make a complete trace claim it was capped

- Source: `acceptance-auditor+edge-case-hunter`
- Location: `server/meetingminer/api/threads.py:280`, `server/meetingminer/api/threads.py:302`, `server/meetingminer/api/threads.py:1059`
- Triage: `patch`
- State: remediated red-first

`_TRACE_STOPS` reports `COUNT(*)` topic-mention rows while `_TRACE_MOMENTS`
quotes distinct `moment` rows selected through `IN`. A derived thread can contain
two synonymous topics attached to the same moment, so one quoted moment is
counted twice in `mentionTotal`. `_assemble_trace` then compares the distinct
quoted rows to that larger total and prints a capped `N of M moments` sentence
even when every distinct moment is present. This violates the story's central
honesty rule and the explicit claim that the two cap figures describe the same
row set. The fix must count subject occurrences on the same distinct-moment row
set the quoting query uses, while retaining every meeting stop.

Red evidence: `test_synonymous_topics_on_one_moment_do_not_fake_a_cap`
failed with `mentionCount [2, 1]` against the unfixed query. The stop aggregate
now counts distinct live moment ids, matching the row set `_TRACE_MOMENTS`
quotes.

### F2 — High — Navigating from a thread deep link to `/threads` keeps the old trace visible

- Source: `acceptance-auditor+edge-case-hunter`
- Location: `web/src/features/threads/ThreadTrace.tsx:76`
- Triage: `patch`
- State: remediated red-first

The route effect loads when `threadId` is present but does nothing when it
becomes absent. React Router can reuse the same `ThreadTrace` component across
the sibling `/threads/:threadId` and `/threads` routes, preserving component
state. Following the primary Threads navigation from a deep link therefore
leaves the previous timeline on the supposedly empty front door; an in-flight
deep-link response can also land after the route became bare. This recreates
the exact interaction Story 10.7 exists to remove. The bare route must clear the
query/trace/refusal state and invalidate any older request generation.

Red evidence: `returns to the empty front door from a deep-linked subject`
could not find the empty-state heading after navigating to `/threads`; the old
trace and input remained visible. The route effect now clears the bare route
and advances the request generation before an older response can land.

### F3 — Medium — Initial fitting can use the 1000px fallback instead of the rendered width

- Source: `edge-case-hunter+verification-gap`
- Location: `web/src/features/threads/TraceTimeline.tsx:76`, `web/src/features/threads/TraceTimeline.tsx:110`, `web/src/features/threads/TraceTimeline.tsx:127`
- Triage: `patch`
- State: remediated red-first

The first passive fit can consume the state initializer's 1000px width and mark
the trace label fitted while the layout effect is publishing the element's real
width. The rerender with the measured width then refuses to fit again because
the label is already recorded. On a viewport narrower than 1000px, the final
meeting can start off-screen even though the view claims to open where the whole
span fits. Fitting ownership must include the measured width (and trace extent),
not only the label, without resetting a reader's zoom after the same measurement
has already been applied.

Red evidence: `fits the whole span to the rendered width, not the fallback
width` received `data-ppd="7.46"` at a 500px rendered width instead of `3.22`,
and the final stop was culled. The component now waits for a positive layout
measurement in browsers, uses 1000px only when no layout observer exists, and
keys first-fit ownership to the trace's identity and extent.
