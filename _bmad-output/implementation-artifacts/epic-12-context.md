# Epic 12 Context: Meeting-Level Analysis

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Extraction already reasons over a whole transcript, but everything it produces is
stored and displayed per moment and the document the model wrote is thrown away.
On the corpus measured 2026-08-31 that means 45 extraction runs, 193 artifacts and
zero retained documents — and a meeting holding sixteen artifacts whose moment view
reports "Nothing extracted yet", because no single moment carries them. This epic
keeps the text each run produced, gives a meeting a first-class summary artifact
scoped to the meeting rather than to a moment, shows a meeting's whole analysis at
the meeting, and makes the retained documents findable in search and chat. The
owner's framing: the generated markdown not being retained is a significant gap,
and artifacts must be visible at the meeting level.

## Stories

- Story 12.1: Retain the Extraction Documents
- Story 12.2: The Meeting Summary
- Story 12.3: The Meeting Analysis Panel
- Story 12.4: Extraction Documents Are Searchable

## Requirements & Constraints

- Every extraction run's full document text is persisted alongside the row that
  already records the run's kind, model, prompt hash, checksum and byte size, and
  the stored bytes must be the exact bytes the parser read so the recorded checksum
  verifies against them. Both origins are stored the same way and read back through
  one path: a document generated by the extraction model, and one a source drop
  already carried.
- A rerun replaces a meeting's document wholesale alongside the artifacts derived
  from it, so a stored document never describes a run whose artifacts have changed.
- A document that parsed to zero items is retained regardless, and the existing
  named zero-parse signal still fires — that run's text is precisely the one a
  reader needs.
- The document is served as the markdown the model emitted, not re-rendered, so a
  reader sees everything including what the parser ignored.
- A meeting's summary becomes a real artifact of a new `summary` kind, scoped to the
  meeting. No summary is fabricated for a document that carries none; decision rows
  keep becoming ADR artifacts as before.
- A meeting-scoped artifact is not an exception to human-approved publishing: it
  enters the same `extracted → approved → published` lifecycle and publishes by the
  same gesture, and the per-moment approval path keeps working unchanged.
- One endpoint returns every artifact for a meeting — summary, ADRs, action items —
  with each one's moment anchor where it has one, replacing the per-moment fan-out
  the meeting view does today. The retained documents are reachable from the meeting
  as the source text an artifact came from, labelled with the model and prompt that
  produced it.
- The artifact kind list rendered in the rail carries only kinds the pipeline can
  actually produce; the kinds that render a permanent zero are removed, so a zero
  reads as "none in this meeting" rather than "never produced".
- Extraction documents are indexed as soon as they are stored, ungated by approval,
  and re-indexed by `rebuild` from their database row alone.
- Every indexed or rendered document carries its unreviewed, machine-written status
  **in the indexed record itself**, not only in the UI.
- A document is never a citation target, and a test must assert no citation resolves
  to one.

## Technical Decisions

- **Searchable text is a database row, not a file (AD-3, as amended 2026-08-31).**
  The content root holds binaries the system serves but does not retrieve over
  (frames, screenshots, audio). Extraction document text must be searchable, and the
  projection layer opens no evidence file, so text living only in a drop could not be
  indexed and would drop out of search on every rebuild. Store it in Postgres for
  both origins — the precedent is the existing artifact body column. The recording
  staying in its drop is not a general rule against copying arrived material in.
- **Projections have exactly one writer, and this epic adds the first deliberate
  exception to the publish gate (AD-4).** All graph and search writes still go
  through the projections module, which still reads Postgres plus `config.yaml`
  alone; `rebuild` regenerates both stores from those. The gate refuses unpublished
  *artifacts*; extraction documents bypass it because the run whose text somebody
  needs is the run that yielded nothing worth approving. The exception is to reach,
  never to legibility.
- **Human approval still governs artifacts (AD-6).** The summary is an artifact and
  is gated like every other one.
- **Citation scope does not widen (AD-6, AD-15).** A citation is a moment id with
  start and end offsets, because the promise is that a citation opens the recording
  at the second. `meeting_id` is scope and provenance, never a citation. A summary's
  or document's content reaches an answer only through the moments its individual
  claims anchor to; unanchored prose stays readable and findable without becoming
  citable.
- **Nothing degrades silently (AD-18).** Unreviewed machine output must never read
  the same as reviewed output — hence the status carried in the indexed record and
  on every rendering surface, the same requirement topics and threads already meet.
- **Schema shape.** The artifact's moment reference becomes nullable, with a
  constraint requiring it null for meeting-scoped kinds and present for
  moment-anchored ones; the meeting reference stays required for both. Which kinds
  are meeting-scoped is declared in exactly one place — that constraint — so no
  reader keeps its own copy of the list. The existing composite edge pinning an
  artifact's moment to that moment's own meeting still holds wherever a moment is
  named.
- **Document chunk identity.** A document has no transcript segment and so takes no
  chunk identity from one; its indexed identity derives from its extraction-run row.
  Because it is not citable, that identity is a build decision — pick one, state it,
  and pin it with a test.
- **Keep the gate's own account of itself true.** The publish-gate module's docstring
  must name the extraction-document exception and point at AD-4.

## UX & Interaction Patterns

- The meeting view shows the summary first, then ADRs and action items grouped by
  kind, each stating its timestamp and linking to the moment it anchors to. A meeting
  holding artifacts never reports "Nothing extracted yet".
- The moment view's existing per-moment rail is unchanged — this epic adds the
  meeting scope, it does not move the moment one.
- Machine-derived, unreviewed content is labelled wherever it renders, following the
  existing pattern used for topics and threads. Absence is stated in the quiet muted
  voice rather than left as a blank that reads as a rendering failure.
- The meeting view keeps its established reading-width, mono-dense presentation and
  its counted section headers; it is not redesigned here.

## Cross-Story Dependencies

- 12.2, 12.3 and 12.4 all depend on 12.1 landing the retained document text: the
  summary is parsed from a document, the panel links artifacts back to their source
  document, and 12.4 indexes what 12.1 stores.
- 12.3's meeting-artifacts endpoint depends on 12.2's meeting-scoped artifact schema,
  since a meeting-scoped summary has no moment anchor to return.
- 12.4 changes the publish gate's behaviour that Epic 4 established and that Epic 5's
  publish-gate eval check asserts — the gate still refuses unpublished artifacts;
  only documents are excepted.
- The extract stage and its strict parser come from Epic 4; the meeting and moment
  views come from Epic 2; topics and threads (Epic 10) supply the existing
  machine-derived labelling convention this epic reuses.
