## Findings

### 10.6-F1 — Timeline parser rejects Story 10.3's actual response shapes (must fix)

`web/src/features/threads/threadsApi.ts:143-195` parses the speculative build-time
shape (`buckets[].from/to`, `meetings[].durationMs`, and
`moments[].meetingTitle`). Story 10.3 now serves `bands[].startAt/endAt`, meeting
spans as `occurredAt/lastOccurredAt`, and moments without `meetingTitle`
(`story/10-3:server/meetingminer/api/threads.py:319-435`). Against that real
contract, every bands response fails at the envelope, every meeting fails on
`durationMs`, and every moment fails on `meetingTitle`, leaving the outgoing
tier and a refusal instead of the requested timeline. Reconcile the client
types/parser/rendering with the landed wire shape and lock the contract with a
regression test built from the server's actual JSON.

### 10.6-F2 — Tier Retry clears the refusal but issues no request (high, patch)

`web/src/features/threads/Threads.tsx:224-227` clears an error and mutates
`requestedKeyRef`, but the fetch effect depends only on `wanted` and `tier`.
Neither changes, so Retry removes the refusal without retrying. Add an owned
retry trigger and prove one click starts one replacement request.

### 10.6-F3 — Cache/null transitions do not invalidate older generations (high, patch)

`web/src/features/threads/Threads.tsx:129-187` advances the generation only for
an uncached request and accepts a result by generation alone. Returning to a
cached window, or moving to a state with no wanted request, lets an older body
that completes across abort overwrite the newer visible state or leave
`aria-busy` stuck. Every desired-key transition must invalidate prior work and
completion must still own both its generation and key.

### 10.6-F4 — View math and CSS tracks use different coordinate systems (high, patch)

`web/src/features/threads/useTimelineView.ts:143-160` measures the whole grid,
while each data track in `TimelineCanvas.tsx:497-512` starts after a 150px row
header and 12px gap. Axis ticks start at the outer origin, fit/fetch use the
larger width, and wheel focus is measured from the padded scroll region. The
instant under the pointer therefore moves during zoom and Fit does not fit the
actual track. Establish one measured data-track width and origin for axis,
fetch, fit, controls, CSS placement, and pointer focus.

### 10.6-F5 — Keyboard Enter on a bucket never selects its thread (high, patch)

Pointer activation at `TimelineCanvas.tsx:385-390` selects the bucket's thread
and fits it; `handleKeyDown` at lines 246-249 only fits. Crossing to meetings
with `focusedThreadId === null` produces `wanted.ids = []`, so no meetings
request is made and keyboard drilling stalls. Keyboard activation must perform
the cell-kind-specific action used by pointer activation.

### 10.6-F6 — Fine-tier payloads are relabelled with a new thread and keep stale brackets (high, patch)

`Threads.tsx:42-49,213-215,361-394` does not record which thread owns `drawn`,
and keeps meeting brackets in one global ref. Selecting another thread changes
the header and palette immediately while the old layer remains, then new
moments can render over the prior thread's meeting brackets. A drawn layer and
its brackets must retain their owner until a matching replacement lands; cache
restores must restore the matching meeting context too.

### 10.6-F7 — Empty buckets and empty tiers break roving focus (high, patch)

`TimelineCanvas.tsx:753-767` includes zero-mention buckets in its cell model
even though no gridcell is rendered, so initial/arrow focus can select a DOM
node that does not exist. At lines 155-175 an incoming tier with zero cells
returns without restoring focus, and the grid root is not focusable, so focus
falls to the page. Exclude empty buckets, skip empty rows during vertical
navigation, and focus the grid root with the named empty-state announcement
when no replacement cell exists.

### 10.6-F8 — Advertised Shift-arrow pan performs ordinary cell navigation (medium, patch)

`TimelineCanvas.tsx:204-241` handles ArrowLeft/ArrowRight before consulting
`event.shiftKey`. The controls claim `Shift+←` / `Shift+→` pan 80%, but the keys
move roving focus. Implement and test the advertised keyboard operation.

### 10.6-F9 — Sorting reorders the list but not its timeline bands (medium, patch)

`ThreadList.tsx:70` sorts a private array, while `Threads.tsx:308` passes the
original API order to the canvas. The design contract says band rows follow
list order, so list and grid contradict one another after either sort. Derive
one ordered array and give it to both consumers without making color depend on
position.

### 10.6-F10 — A short corpus opens in a finer tier with no focused thread (high, patch)

`Threads.tsx:73-82,108-127` fits the corpus and immediately derives the tier
from that scale. A corpus shorter than roughly 83 days at 1000px fits below the
bands threshold, producing meetings/moments with `ids = []` instead of the
required opening view of every thread as bands. Home/open must fit the corpus
while preserving the bands-tier floor.

### 10.6-F11 — Malformed and capped payloads can become half-drawn data or a false outage (high, patch)

`threadsApi.ts:118-195,223-271` never applies `instantOf` to parsed timestamps,
silently normalizes malformed `speakers`, ignores Story 10.3's `truncated`
flag, classifies JSON/schema errors as transport outages, and stops its timeout
once headers arrive rather than after the body. Invalid instants reach CSS as
`NaN`; capped moments look complete; a reachable API is reported as
unreachable; a stalled body can wait forever. Validate the complete live
shape, reject capped/incomplete tiers by name, distinguish contract refusals
from transport, and keep expiry ownership through body parsing.

### 10.6-F12 — Moment labels overlap before the clustering rule activates (medium, patch)

`timeline.ts:289-325` clusters at 24px, but `TimelineCanvas.tsx:691-710` makes
each moment cell 120px wide. Items 24-119px apart remain separate while their
labels and hit areas overlap. Cluster using the actual interactive geometry
and lock that threshold with a regression test.

### 10.6-F13 — Required pointer interactions and bucket focus affordance are absent (medium, patch)

`TimelineCanvas.tsx:283-304,503-533` has wheel pan/zoom and click only: no drag
pan, no double-click-to-fit, and no hover/focus count/date popover or cursor
line even though the CSS classes exist. Implement these specified operations
without adding a hover-only path.

### 10.6-F14 — Route parameter changes can leave the prior thread selected (medium, patch)

`Threads.tsx:59-65` copies `routeThreadId` into state only during mount. React
reuses the route component for `/threads/a` → `/threads/b`, so the URL can name
B while finer requests and selection remain on A. Synchronize param changes
and test navigation without remounting.

### 10.6-F15 — Off-screen padded buckets alter visible density (medium, patch)

`TimelineCanvas.tsx:482-484` computes density quartiles from the whole padded
fetch response, while the visual contract defines quartiles over visible bands
in the window. Filter the density population to buckets intersecting the
visible span.

### 10.6-F16 — Tier replacement is a fade-in, not the specified cross-fade (medium, patch)

`TimelineCanvas.tsx:375-421` unmounts the outgoing layer immediately and
`threads.css:65-77` only fades the incoming layer from transparent. Preserve a
non-interactive outgoing snapshot for 160ms while the incoming layer fades at
the same coordinates.

### 10.6-F17 — Demo-critical CSS geometry has no durable browser check (open: owner/tooling decision)

The normal tests compare `xOf` with itself under jsdom; none executes
`.mm-at/.mm-span` layout in a browser. The requested Chrome rerun is blocked in
this session because no Chrome browser connection is available. Adding a
checked-in browser test also requires choosing and wiring browser-test tooling
outside this story's frozen footprint. The owner must choose that harness (or
provide Chrome connectivity) before this can be closed honestly.

### 10.6-F18 — A thread-only deep link has no specified time anchor (open: frozen-spec decision)

The loaded UX flow says `/threads/:threadId` opens at meetings around the
calling moment, but the route carries only `threadId`; the frozen Story 10.6
spec tests only that the thread is selected. Choosing latest mention, the whole
thread span, or a fixed window would invent navigation semantics. The owner
must decide whether thread chips add a time/window parameter or which server
field anchors the initial meetings view. This review will not silently choose
one.
