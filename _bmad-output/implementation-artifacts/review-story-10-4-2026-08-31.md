## Findings

### F1 — Recency contributions disappear after one half-life instead of decaying

- **Location:** `server/meetingminer/api/moments_feed.py:472-515`
- **Severity:** high
- **Route:** patch
- **Finding:** The meeting and publication recency terms are added only inside
  the same `factor >= 0.5` guard that controls whether their reasons are shown.
  The frozen contract says the term always scores while the reason is hidden
  after one half-life, and `config.yaml` explicitly promises quarter weight at
  28 days and no cutoff.
- **Observed consequence:** A candidate exactly 28 days old scored `0.0` with
  the shipped config even though `recency_factor()` returned `0.25`. A 15-day
  old ADR therefore ties a year-old ADR instead of retaining a decayed recency
  advantage, and the feed can reorder discontinuously overnight.
- **Required remediation:** Keep the decayed score term at every age while
  emitting `recency`/`published` reasons only inside the truthful reason window;
  preserve explainability without claiming stale evidence is recent.

### F2 — Multiple timed action rows multiply a categorical weight

- **Location:** `server/meetingminer/api/moments_feed.py:408-446`
- **Severity:** high
- **Route:** patch
- **Finding:** Every timed action artifact adds the full
  `action_item_stated_timing` and urgency weights. This contradicts the frozen
  once-per-kind rule and lets a talkative moment dominate the front door.
- **Observed consequence:** With the shipped config, one identical due action
  scored `6.714285714285714`; two scored `13.428571428571429`.
- **Required remediation:** Earn the stated-timing category once and use the
  strongest/soonest valid action for the urgency term, with deterministic
  selection and bounded explanatory reasons.

### F3 — Thread count, invalid names, and uncapped wire chips violate the thread contract

- **Location:** `server/meetingminer/api/moments_feed.py:517-532,612-641`
- **Severity:** medium
- **Route:** patch
- **Finding:** Thread score scales from one-third to the full configured weight
  as memberships grow; a blank thread name can contribute score after its
  reason is discarded; and `to_item()` serializes every membership even though
  `max_thread_reasons` says how many chips may appear.
- **Observed consequence:** One thread scored `0.3333333333333333`, three
  scored `1.0`, and a blank thread increased an ADR candidate from `5.0` to
  `5.333333333333333` while the only surviving reason still described the ADR.
- **Required remediation:** Sanitize and deterministically cap threads once,
  award `thread_membership` exactly once when any valid membership remains,
  and use that same bounded set for reasons and `threads[]`.

### F4 — Timed action items disappear from the `kind=action-item` feed

- **Location:** `server/meetingminer/api/moments_feed.py:408-446,883-890`
- **Severity:** medium
- **Route:** patch
- **Finding:** A timed action emits only one combined `due` reason. Because the
  route defines `kind` as a reason-kind filter, `kind=action-item` retains
  untimed zero-weight actions but excludes the timed commitments the score is
  specifically meant to prioritize.
- **Required remediation:** Represent the categorical action contribution as
  an `action-item` reason and the calendar urgency as a separate `due` reason,
  so both filters remain truthful and the ordered reasons explain both terms.

### F5 — Free-text timing parsing both misses and invents urgency

- **Location:** `server/meetingminer/api/moments_feed.py:247-315`
- **Severity:** medium
- **Route:** patch
- **Finding:** The substring label matcher treats `Blocked by:` as the timing
  field, returns immediately on an empty/`not stated` matching line instead of
  considering a later actual timing line, and recognizes only ISO and numeric
  US dates. Common full calendar spellings preserved by the summarizer, such as
  `September 4, 2026`, receive no urgency; a dependency can receive stated-time
  weight instead.
- **Observed consequence:** `Blocked by: vendor approval\nTiming: not stated`
  returned `vendor approval`, while `September 4, 2026` returned no date.
- **Required remediation:** Match complete supported timing labels, continue
  past blank/unstated candidates, accept unambiguous full calendar dates with a
  year, and continue past malformed date-shaped tokens to a later valid token.

### F6 — The production extraction-to-feed handoff and replacement rules are unverified

- **Location:** `server/meetingminer/pipeline/stages/extract.py:359-365,653-760`
- **Severity:** medium
- **Route:** patch (coverage)
- **Finding:** Parser tests stop before the stage, feed tests insert
  `ranking_signal` directly, and worker tests give the fourth pass an empty
  document. No test proves a non-empty R/Q reply persists the right anchored
  rows and provenance, appears in the feed, replaces old rows on rerun, clears
  on early exit, skips superseded anchors, or receives exactly one retry.
- **Mutation consequence:** Removing `_INSERT_RANKING_SIGNAL`, mis-mapping its
  fields, or dropping `_DELETE_RANKING_SIGNALS` leaves the shipped story tests
  green while real ingestion produces no usable signals or retains retracted
  ones.
- **Required remediation:** Add focused stage-level red/mutation evidence for
  the worker-owned row, source counts, replacement/early-exit cleanup,
  superseded discard, retry discipline, and the feed consumer handoff.

### F7 — Ranking configuration accepts infinity

- **Location:** `server/meetingminer/config.py:933-990`
- **Severity:** medium
- **Route:** patch
- **Finding:** The float fields constrain sign but not finiteness. Pydantic
  accepted `adr=float('inf')`; infinite weights collapse meaningful score
  distinctions, while infinite half-life/horizon values silently defeat the
  recorded decay and urgency rules.
- **Required remediation:** Set `allow_inf_nan=False` on every ranking float
  and add load-boundary regressions naming the invalid key.

### F8 — Conflicting duplicate signal IDs are silently discarded

- **Location:** `server/meetingminer/pipeline/extraction.py:1112-1123`
- **Severity:** medium
- **Route:** patch
- **Finding:** Ranking-signal IDs are document-global, but duplicate R/Q IDs
  inherit the artifact parser's “first definition wins” behavior. The prompt
  requires one row per item with all timestamps on that row; a conflicting
  duplicate is malformed model output and should earn the existing one-retry
  discipline, not silent data loss.
- **Observed consequence:** Two different `R1` rows parsed successfully as only
  the first row.
- **Required remediation:** Refuse duplicate ranking-signal IDs by name, as the
  topic parser already does, and cover the parser and generated retry boundary.

### F9 — Offset pages have no stable ranking snapshot across requests

- **Location:** `server/meetingminer/api/moments_feed.py:824-893`
- **Severity:** medium
- **Route:** decision needed / frozen-spec gap
- **Finding:** Each page request chooses a new `now`. Fixed artifact terms plus
  continuously decaying recency/publication terms can cross between page calls,
  so an unchanged candidate can move across an offset boundary and be returned
  twice while another is skipped. The in-request invariant
  `offset + len(items) <= total` holds; the multi-request no-repeat guarantee
  does not have a snapshot mechanism.
- **Owner decision needed:** A correct patch requires a wire-level choice such
  as a client-supplied `asOf`, an opaque cursor, or an explicit relaxation of
  the frozen paging guarantee. This review will not silently add a sixteenth
  input to the Story 10.5 client contract.
