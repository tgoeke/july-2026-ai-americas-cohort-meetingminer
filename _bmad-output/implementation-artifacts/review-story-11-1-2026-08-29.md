## Findings

### 1. The documented budget override makes the plugin's own real-session test fail

- **Location** — `server/tests/test_fast_budget.py:108`
- **Severity** — medium
- **Finding** — The plugin documents `-o mm_fast_test_budget_seconds=<seconds>` as a supported per-run override, but the real-session wiring test asserts that the effective value is exactly `2.0`. Any valid override other than `2.0` therefore makes an otherwise healthy run fail.
- **Evidence** — `uv run --project server pytest -q server/tests/test_fast_budget.py::test_the_real_session_loads_fast_budget_from_conftest -o mm_fast_test_budget_seconds=3.0` returned 1 with `AssertionError: assert 3.0 == 2.0` at line 108.
- **Suggested direction** — Test that the plugin is loaded and that the configured value is valid without pinning the effective value after command-line overrides; keep the literal pyproject default pinned in the separate TOML contract test.

### 2. A `-k` miss on fast tests prints an incorrect slow-module hint

- **Location** — `server/tests/fast_budget.py:127`
- **Severity** — medium
- **Finding** — The session-finish hook treats any exit-5 run with the default marker expression and at least one deselected test as if every item was deselected by `-m "not slow"`. Deselecting a fast module entirely with `-k` meets those conditions, so the hint recommends `-m ""` even though clearing the marker expression cannot select the requested nonexistent test.
- **Evidence** — `uv run --project server pytest -q server/tests/test_config.py -k __meetingminer_no_such_test__` returned 5 after deselecting 55 fast tests and printed `every collected test was deselected by the default -m "not slow" ... a slow module run by path needs -m ""`.
- **Suggested direction** — Track whether marker filtering actually removed every originally collected item, and add a pytester regression covering both a slow-only path and an unrelated all-deselected `-k` run.

### 3. The full-gate contract does not verify the effective marker selection

- **Location** — `server/tests/test_compose_contract.py:85`
- **Severity** — medium
- **Finding** — The regression test only checks that the `test` recipe contains the substring `-m ""`; it does not verify which marker expression pytest ultimately receives. A later `-m "not slow"` would still satisfy the contract while silently dropping all 326 slow tests from the full gate.
- **Evidence** — Lines 85–87 contain only `assert '-m ""' in _recipe("test")`. Pytest accepts repeated `-m` options with the later value effective: `pytest --co -q -m "" -m "not slow" server/tests/test_projections_locks.py` returned 5 with `no tests collected (9 deselected)`.
- **Suggested direction** — Exercise or capture the Make target's effective pytest argv and assert one clearing marker expression with no later replacement, ideally with a slow sentinel proving inclusion.

### 4. The `test-fast` contract can stay green after most or all server tests disappear from the target

- **Location** — `server/tests/test_compose_contract.py:95`
- **Severity** — medium
- **Finding** — The only `test-fast` recipe assertions require the text `-rs` and forbid `MM_REQUIRE_TEST_STORES`. They do not assert that pytest runs, that its path is `server/tests`, or that the effective selection is the fast set. Replacing the server command with `pytest -q -rs server/tests/test_config.py`, or even an inert command containing `-rs`, leaves this contract green while the advertised loop stops checking almost all server behavior.
- **Evidence** — Lines 95–99 are the complete test and make no assertion about `pytest`, `server/tests`, or the marker expression; a repository search found no other test executing or capturing the `test-fast` target.
- **Suggested direction** — Add a fake-command Make invocation, following the existing process-target test pattern, and assert the captured pytest project, test root, skip-reporting flag, and effective `not slow` selection.

### 5. The canonical slow-module contract checks only a spoofable subset

- **Location** — `server/tests/test_compose_contract.py:127`
- **Severity** — medium
- **Finding** — `SLOW_MODULES` is described as the measured canonical set, but the parametrized test only proves that every listed file contains a source line beginning with `pytestmark = pytest.mark.slow(`. It never detects an additional module-level slow mark, and a matching line inside a top-level multiline string satisfies the check without applying any pytest mark. The fast suite can therefore shrink while this guard remains green.
- **Evidence** — Lines 146–152 iterate only over `SLOW_MODULES` and perform a raw `source.splitlines()` prefix search; there is no reverse scan or collected-marker assertion elsewhere in the tree.
- **Suggested direction** — Derive the actual module-level slow set with syntax-aware inspection or collection metadata and compare it exactly with the expected set, including proof that each expected mark is effective.

### 6. Invalid configured budgets have no regression coverage

- **Location** — `server/tests/fast_budget.py:55`
- **Severity** — low
- **Finding** — The plugin explicitly promises named usage errors for nonnumeric, NaN, infinite, zero, and negative values, but the pytester suite exercises only a valid `0.05` override and the repository contract only checks the current positive value. Removing any part of the validation branch leaves all tests green.
- **Evidence** — `server/tests/test_fast_budget.py:66-77` supplies only `0.05`; its six tests contain no invalid override. `test_compose_contract.py:121-124` validates only the checked-in TOML value.
- **Suggested direction** — Parameterize pytester runs over representative invalid values and assert `USAGE_ERROR`, the configuration key, and the offending value.

### 7. The non-strict XPASS exemption is untested

- **Location** — `server/tests/fast_budget.py:105`
- **Severity** — low
- **Finding** — The report hook deliberately exempts reports carrying `wasxfail`, and both the plugin documentation and triage history call that behavior out, but no pytester probe exercises it. A change in hook/report semantics could turn an expected non-strict XPASS into a budget failure without any focused regression failing.
- **Evidence** — The only probe cases in `server/tests/test_fast_budget.py:19-41` are unmarked pass, ordinary failure, slow-marked pass, and fast pass; no `xfail` or XPASS case exists.
- **Suggested direction** — Add a non-strict `xfail` sleeper that unexpectedly passes over budget and assert its native XPASS outcome is preserved.

### 8. Slow-mark validation is not tested under the default deselection path

- **Location** — `server/tests/test_fast_budget.py:147`
- **Severity** — low
- **Finding** — The collection hook's `tryfirst=True` ordering is essential: it must reject a reasonless slow mark before pytest's default `-m "not slow"` hook removes that item. The probe runs with an empty ini and no marker expression, so it verifies the rule only when the marked item remains selected.
- **Evidence** — `_inner_run` at lines 66–77 passes no `-m` option; `test_a_slow_mark_without_a_reason_stops_collection` at lines 147–151 uses only that unfiltered helper. Changing the implementation hook to run after deselection would keep the existing probe green while breaking the normal path.
- **Suggested direction** — Run the reasonless-slow probe with `-m "not slow"` and require the same usage error and node id.

### 9. The frozen outcome/count contract contradicts the story's required regression tests

- **Location** — `_bmad-output/implementation-artifacts/spec-11-1-seconds-fast-default-suite.md:45`
- **Severity** — medium
- **Finding** — The spec requires the post-change per-test outcome set and exact totals to equal the 1,683-test baseline, while the implementation plan and review hardening require permanent contract tests. The story adds 24 tests and one additional slow-marked existing test, producing the recorded 1,707-test result before rebase; after rebasing over current `main`, collection is 1,708. The empty Spec Change Log never reconciles this impossible acceptance condition, so the code cannot honestly satisfy the frozen contract as written.
- **Evidence** — Spec lines 45, 47, 55–56, and 93–95 require baseline equality and the old totals. The submitted handoff records 24 added tests and `1381/1707 (326 deselected)`; this review observed `1382/1708 (326 deselected)` after the no-overlap rebase.
- **Suggested direction** — Amend and re-derive the spec so outcome equality applies to baseline node ids while explicitly allowing the named new regression tests, and pin any snapshot totals to a stated revision. Do not delete useful tests merely to satisfy stale totals.
- **Decision** — Amend the spec as suggested: baseline equality applies to pre-existing node ids, named new regression tests are allowed, and totals are revision-pinned. Resolved by the owner on 2026-08-29; route as a patch action.

### 10. The stores-down contract promises twin-store skips that the fast selection cannot produce

- **Location** — `_bmad-output/implementation-artifacts/spec-11-1-seconds-fast-default-suite.md:62`
- **Severity** — medium
- **Finding** — The frozen edge-case row says a Postgres or test-twin outage during `make test-fast` produces named store-backed skips, and the Makefile/help prose repeats that implication. In reality every twin-bound test is marked slow or rejected at collection, so the default selection deselects all of them before fixture setup; taking only the twins down produces zero skips. The implementation behavior is coherent, but its contract and operator-facing explanation are not.
- **Evidence** — `fast_budget.py:81-94` forbids an unmarked `projection_stores`/`stores_up` consumer and `server/pyproject.toml:110` deselects every slow item. The submitted verification explicitly observed `1381 passed, 326 deselected`, with `0 SKIPPED` lines, when both twin endpoints were unreachable. `infra/Makefile:94` and `:286-288` still say store-backed tests skip with reasons.
- **Suggested direction** — Amend the spec and docs to distinguish Postgres-backed fast tests (which can skip) from twin-bound slow tests (which are deselected), while retaining `make test` as the gate that requires the twins.
- **Decision** — Amend the spec and docs as suggested; do not widen `test-fast` to execute twin-bound tests. Resolved by the owner on 2026-08-29; route as a patch action.
