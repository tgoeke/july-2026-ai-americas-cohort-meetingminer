# Review — Story 12.2: The Meeting Summary

## Scope

Adversarial review and red-first remediation of Story 12.2 on
`story/12-2-review`, covering the story-owned files and frozen intent boundaries
declared in the review contract.

## Range

Original review range `d250cf89..544d3a8e`, rebased without dropping story
commits onto final `origin/main` at `233b2d98`. The final post-rebase
implementation range is `233b2d98..4094f1f2`; later review/remediation commits
are excluded from that implementation range.

## Findings

### 1. Valid prose-only summaries are rejected

- **Location** — `server/meetingminer/pipeline/extraction.py:1266`
- **Severity** — high
- **Finding** — The parser still requires a table or bullet in a recognized
  target section even after it recognizes an Executive Summary heading. A
  document consisting of the required heading plus ordinary prose is valid per
  the frozen I/O matrix, but raises `ArtifactParseError`; an empty Executive
  Summary section is also supposed to succeed with no summary artifact.
- **Evidence** — Running `parse_extraction_document("# Executive Summary\\nPlain
  prose only.", "arch-summary")` raised `ArtifactParseError: ... neither a
  markdown table row nor a bullet list ...`. Reading the loop showed the
  heading only toggles `in_summary`; only a parsed table/bullet can set
  `target_structure_seen` at line 1134, and line 1266 unconditionally requires
  that flag.
- **Suggested direction** — Treat recognition of the Executive Summary heading
  as recognized architecture-summary structure independently of whether its
  body is prose, a list, or empty; retain the existing structure requirement
  for document kinds without that scope.

### 2. Stored summary prose is not verbatim

- **Location** — `server/meetingminer/pipeline/extraction.py:1071`
- **Severity** — high
- **Finding** — The parser normalizes the entire document before collecting
  Executive Summary lines. NFKC plus punctuation translation changes smart
  quotes, dashes, compatibility characters, and spaces in the persisted summary
  body, violating the frozen requirement to store the section's body verbatim
  and weakening its provenance to the retained source document.
- **Evidence** — Running the parser on `Decision used “smart quotes” — exactly.`
  produced summary text `Decision used "smart quotes" - exactly.`. The code at
  line 1104 iterates `normalized.splitlines()` and appends that normalized line
  at line 1122.
- **Suggested direction** — Continue parsing normalized line text for headings,
  item IDs, and anchors, but retain the corresponding source line for summary
  collection so only the section's outer blank space is stripped.

### 3. A captured summary is logged as zero artifacts

- **Location** — `server/meetingminer/pipeline/stages/extract.py:703`
- **Severity** — medium
- **Finding** — `zero_signals` is populated whenever the existing per-moment
  artifact tuple is empty, without considering the newly captured meeting
  summary. A summary-only document with list-shaped prose therefore persists a
  summary and simultaneously emits `stage.extract.zero_artifacts`, making a
  successful extraction indistinguishable from the no-output condition the
  signal is designed to expose.
- **Evidence** — The branch is `if not parsed.artifacts and
  parsed.populated_target_sections`; `parsed.summary` is not part of the
  decision, although the same stage inserts it and counts it in `item_count` and
  `artifact_count`.
- **Suggested direction** — Define zero output as neither per-moment artifacts
  nor a captured summary, and pin the summary-only stage behavior with a log
  assertion.

### 4. Rebuild silently skips published meeting-scoped artifacts

- **Location** — `server/meetingminer/projections/__init__.py:436`
- **Severity** — medium
- **Finding** — The approve-by-id projection path names a meeting-scoped skip,
  but `rebuild --meeting` calls `published_artifacts(meeting_id=...)` and never
  runs the named-skip query. The summary is correctly excluded from both stores,
  yet a rebuild silently omits it in conflict with AD-18 and the route's own
  recovery instruction.
- **Evidence** — `_project_one` reads only `published_artifacts` before its
  structural write. `meeting_scoped_published` is called only inside
  `project_published_artifacts` when `artifact_ids is not None`; no rebuild-path
  call or `projection.artifact_skipped` event exists.
- **Suggested direction** — Add one nullability-based meeting-scope read to the
  structural rebuild path and emit the same named skip event before projecting;
  do not introduce a kind list or a non-citable store record.

### 5. The eval corpus turns a NULL anchor into the string `"None"`

- **Location** — `evals/harness/corpus.py:40`
- **Severity** — high
- **Finding** — The eval corpus reads every artifact after `moment_id` became
  nullable. `artifact_from_row` stringifies the anchor, so a meeting summary
  becomes `moment_id="None"`; the judge then attempts a `%s::uuid` transcript
  read for it, while the publish-gate check incorrectly expects that published
  summary in both citation-bearing stores. This is the third defect of the same
  nullable-column shape and can invalidate an eval verdict.
- **Evidence** — `_ARTIFACTS` filters only `meeting_id`. `artifacts_for` feeds
  those rows to both `judge.py`'s `segments_for_moment(artifact.moment_id)` and
  `checks.py`'s artifact publish-gate check. The former casts the value to UUID;
  the latter assumes every published artifact is projected, which is expressly
  false for a NULL-scoped summary.
- **Suggested direction** — Keep the citation/evidence corpus moment-anchored by
  selecting `moment_id IS NOT NULL`. State that boundary in the corpus contract
  and test it with both meeting- and moment-scoped rows.

### 6. A stale summary index record crosses into chat's citation context

- **Location** — `server/meetingminer/api/chat.py:203`
- **Severity** — medium
- **Finding** — Chat's authoritative Postgres re-read checks publication state
  but not the now-nullable citation anchor. If a summary ID exists in a stale or
  transitional artifacts index, `_read_artifact_context` accepts it, constructs
  a `RetrievedArtifact(moment_id=None)`, and groups it under a NULL key instead
  of rejecting it as a named stale hit. It does not produce a replayable
  citation, but it silently crosses the citation boundary and distorts retrieval
  counts/context assembly.
- **Evidence** — `_ARTIFACT_CONTEXT` has no `a.moment_id IS NOT NULL`; line 613
  assigns the nullable row directly to a UUID-typed field and line 615 uses it
  as the moment-key. By contrast, search resolution remains safe through its
  inner join to `moment`.
- **Suggested direction** — Make the authoritative chat read require a non-NULL
  anchor. Reuse its existing missing-row path so a stale summary hit is dropped
  and logged by name rather than reaching context assembly.

### 7. Approval still hard-codes publication as the projection trigger

- **Location** — `server/meetingminer/api/artifacts.py:263`
- **Severity** — low
- **Finding** — The new meeting-scoped approve route directly invokes artifact
  projection after the external publish transaction and explains that call as
  the route's policy. This behavior is correct for the frozen Story 12.2
  contract, but it hard-codes the assumption the owner has since reversed:
  external publication is not what makes content findable inside MeetingMiner.
- **Evidence** — Lines 263-277 couple the external export/git/UPDATE gesture to
  `project_published_artifacts`; the comment calls this the per-moment route's
  policy. Story 12.4 is building ungated indexing and Story 12.5 is filed to
  decouple indexing from publishing.
- **Suggested direction** — Leave Story 12.2 behavior unchanged. In Story 12.5,
  remove this route-level trigger (and the equivalent per-moment trigger) in
  favor of the general ungated indexing mechanism, keeping external publishing
  solely as provenance/export state.

### 8. The advertised store-free eval suite can wait on the live corpus lock

- **Location** — `evals/tests/test_gate_probe.py:280`
- **Severity** — medium
- **Finding** — `make evals-test`, which is an unconditional `test-fast`
  prerequisite advertised as store-free and safe beside corpus writers, lets
  fake cleanup tests enter the production projection file lock derived from
  the loaded main-store endpoints. A live main-checkout rebuild can therefore
  stall the unit suite for the full 300-second writer timeout and fail it even
  though every search, graph, and database object in the test is fake.
- **Evidence** — The post-final-rebase `make test-fast` passed lint, typecheck,
  puller, and web, then stopped after eight `test_gate_probe.py` cases while the
  owner had `/server/.venv/bin/rebuild --all` running in the main checkout.
  `lsof` showed pytest waiting on
  `meetingminer-projections-262fe3fa5a97e4f3.lock`; after 300 seconds,
  `test_a_clean_cleanup_verifies_every_target` failed with the named projection
  store lock timeout. The review did not touch or interrupt the live rebuild.
- **Suggested direction** — Keep the production lock in the live eval path,
  but inject a fake/no-op lock into cleanup unit tests except the dedicated
  lock-domain assertion. Pin that `make evals-test` cannot open or wait on a
  projection lock derived from the live corpus configuration.

## Disposition

- Findings 1–3 were fixed red-first in `c260efb4`: prose-only and empty
  Executive Summary sections now parse, stored prose remains verbatim while
  recognition stays normalized, and a captured summary no longer emits the
  zero-output signal.
- Findings 5–6 were fixed red-first in `ca250c24`: eval and chat citation
  readers now require `moment_id IS NOT NULL`; a stale summary hit follows
  chat's existing named stale-record path.
- Finding 4 was fixed red-first in `4a719267`: rebuild queries published
  meeting-scoped rows by `moment_id IS NULL` solely to emit the same named skip
  used by approval, while store projection remains moment-anchored.
- Finding 7 remains open by owner ruling for Story 12.5. Story 12.2's current
  external-publish-to-projection coupling was deliberately not changed.
- Finding 8 is open and deferred. It is pre-existing eval-test isolation debt,
  not caused by Story 12.2, and changing Story 11.3's lock tests is outside this
  review's implementation scope.

## Architecture verification

- A repository-wide audit of every production/eval `artifact` query found no
  reader-owned meeting-scope kind list. Migration 0022's
  `artifact_scope_matches_kind` remains the sole meeting-scope declaration;
  scope-sensitive branches use `moment_id IS NULL`, `IS NOT NULL`, equality to
  a real moment, or an inner join to `moment`.
- Migration 0009's composite `(moment_id, meeting_id)` foreign key is untouched.
  The six migration-scope tests include the cross-meeting refusal and passed.
- `api/search.py` remains protected by its inner join to `moment`; chat and the
  eval corpus now explicitly require a non-NULL anchor; projection and digest
  already did so. No meeting summary reaches a citation, replay link, eval
  citation check, Neo4j artifact node, or Meilisearch artifact document.
- The pre-12.2 inline export → ADR git commit → lifecycle `UPDATE` loop was
  compared with `api/artifact_publish.py`. Both approve routes call that one
  implementation; the per-moment ordering and error contract are unchanged.
- `_DELETE_DRAFTS` remains the NULL-safe `NOT EXISTS` /
  `IS NOT DISTINCT FROM` formulation, and the full worker suite passed its
  draft-replacement and approved-scope cases.
