# Code Review — Story 10.1: Topic Extraction

## Scope

Adversarial review of Story 10.1 topic extraction against its frozen intent,
builder contract, architecture authorities, consequential edits, and stated
verification baseline. Findings only; implementation fixes are out of scope.

## Review range

`5cdfce7..3cc35926e09913f2d248ef6dbdc251cd469a9bb9` (`story/10-1`).

## Findings

### 1. Cross-meeting topic mentions satisfy every declared foreign key

- **Location:** `server/meetingminer/migrations/0014_topics.sql:39-51`; `server/tests/test_migrations_topics.py:104-117`
- **Severity:** Medium
- **Finding:** `topic_mention.meeting_id` is constrained to the mentioned moment's meeting, but it is not constrained to the topic's meeting. A topic owned by meeting A can therefore mention a moment owned by meeting B by inserting `(topic_id=A-topic, moment_id=B-moment, meeting_id=B)`. That row satisfies both the scalar `topic_id` foreign key and the `(moment_id, meeting_id)` foreign key, contradicting the migration's same-meeting-integrity claim and allowing the Postgres record to contain cross-meeting navigation edges.
- **Evidence:** `topic_id` references only `topic(id)` at line 39; the only composite foreign key is `(moment_id, meeting_id) → moment(id, meeting_id)` at lines 50-51. The migration test passes `meeting_a` beside `moment_b`, so it proves that a false moment/meeting pair is rejected, but never tries the valid `(moment_b, meeting_b)` pair with the meeting-A topic. No constraint relates `topic_mention.meeting_id` to `topic.meeting_id`.
- **Suggested direction:** Make `(id, meeting_id)` a referenced key on `topic` and add a composite `(topic_id, meeting_id)` foreign key from `topic_mention`, while retaining the moment composite foreign key. Add a regression test that supplies meeting B consistently for the mention while using a topic from meeting A and confirms the insert is refused.

### 2. A repeated topic ID silently loses all later discussion anchors

- **Location:** `server/meetingminer/pipeline/extraction.py:835-841`; `server/tests/test_extraction_topics.py:118-139`
- **Severity:** Medium
- **Finding:** Topic IDs are deduplicated by keeping the first row and silently discarding every later row, including that row's timestamps. Because every heading is accepted for topics, a model response that restates `T1` under a later heading parses successfully but omits every mention carried only by the restatement. This violates the frozen requirement to anchor each topic at every place it was discussed and recreates the silent-loss shape the parser discipline is meant to prevent.
- **Evidence:** The duplicate branch returns before `_anchor_stamps` runs. An executable probe using `T1 | Feed | First | [0:10]` under `## Topics` and `T1 | Feed | Returned later | [0:45]` under `## More topics` returned one artifact with `anchors_ms == (10000,)` while reporting both sections as populated; `[0:45]` disappeared with no error or signal. The dedup test asserts only IDs/titles and therefore stays green while anchors are lost.
- **Suggested direction:** Never silently discard a duplicate topic row. Either merge all of its resolved anchors into the canonical topic (preserving the one-topic/one-mention-per-moment rule) or reject duplicate T-ids as a named parse error so the generated document gets its one retry. Add a regression test that proves the later row's unique anchor cannot disappear.

### 3. Short names and missing required topic fields are misclassified or synthesized

- **Location:** `server/meetingminer/pipeline/extraction.py:636-687,917-943`; `server/tests/test_extraction_topics.py:58-95,194-198`
- **Severity:** Medium
- **Finding:** Topics reuse the artifact parser's generic “first cell longer than two characters” title heuristic and its generic no-detail body fallback. A valid short topic name such as `AI`, `UI`, or `QA` is skipped, so the Gist cell becomes the stored topic name and the original Topic cell becomes the gist. If the Topic cell is empty, the Gist cell is promoted; if the Gist cell is empty, a stock sentence is synthesized. All three rows are accepted despite the migration and intent requiring an extracted name and one-line gist.
- **Evidence:** An executable parse of `| T1 | AI | Model selection | [0:10] |` produced `title='Model selection'`, body `Topic: AI`, and `topic_gist(...) == 'Topic: AI'`. Parsing `| T1 | | Model selection | [0:10] |` stored `name='Model selection'` and the no-detail fallback as gist; parsing `| T1 | Feed | | [0:10] |` stored `gist='No detail was recorded beyond the item text.'`. `_title_and_body` excludes cells with `len(cell) <= 2`, does not select the header-labelled Topic/Gist cells, and replaces an empty body before `topic_gist` can distinguish it; existing tests use only long, non-empty names and gists.
- **Suggested direction:** Give topic rows topic-aware field extraction: use the labelled Topic and Gist columns when present, support the pinned bullet ordering when labels are absent, accept non-empty short names, and reject a missing name or missing gist by item id. Add table and bullet regressions for a two-character name and for each missing required field.

### 4. The labelled timestamp field is only partially authoritative

- **Location:** `server/meetingminer/pipeline/extraction.py:470-485,560-587`; `server/tests/test_extraction_topics.py:85-107`
- **Severity:** Medium
- **Finding:** Once a labelled Timestamps cell contains at least one valid stamp, the parser accepts the row and silently ignores every timestamp-shaped token that fails parsing. Conversely, if that labelled cell has no valid stamp, the parser scans other cells and the raw row, allowing a clock-like value in the topic name or gist to become the citation. Topics uniquely require every place of discussion, so the labelled field can currently produce either an incomplete mention set or a fabricated anchor while the document reports success and receives no retry.
- **Evidence:** `_timestamps_ms` catches `TranscriptParseError` and continues; `_anchor_stamps` immediately returns surviving stamps but falls through to every cell and then the raw row when the labelled field yields none. An executable parse with `Timestamps = [0:10], [99:99]` produces only `(10000,)`; a row whose Timestamps cell says `not stated` but whose gist says `moving the 9:00 standup` resolves `9:00` as the meeting anchor. Existing coverage checks an entirely stamp-free row and fully valid range/comma forms, but neither mixed valid/invalid content nor a clock-like gist beside an invalid labelled field.
- **Suggested direction:** When a topics table supplies a labelled timestamp column, make it authoritative: validate the whole timestamp list and raise a named `ArtifactParseError` if it is empty, malformed, or contains unparsed residue, so `_generate` can retry. Preserve fallback scanning only for genuinely headerless/bullet layouts, and add regressions for mixed valid/invalid content and incidental clock text outside the timestamp field.

### 5. Permissive headings accept a wrong-document T-row as a real topic

- **Location:** `server/meetingminer/pipeline/extraction.py:704-720,808-834`; `server/tests/test_extraction_topics.py:158-179`
- **Severity:** Medium
- **Finding:** Every non-empty heading is a target for the topics parser, and a `T` prefix plus any anchor is sufficient to persist a topic. A malformed or wrong-document response containing task/test IDs under `## Decisions`, `## Notes`, or another unrelated table therefore becomes successful topic extraction instead of earning the generate-path retry. The stage-level zero-topics signal does not mitigate this path because at least one false topic lands.
- **Evidence:** An executable parse of `## Decisions` with headers `ID | Decision | Context | Timestamp` and row `T1 | Rotate key | Required by policy | [0:10]` returned a topic named `Rotate key` with gist `Context: Required by policy`. The existing permissive-heading test proves only the desired `## Discussion themes` drift, while the shared-empty test uses a foreign heading with no rows; neither tests a contentful foreign table using a plausible T-prefixed ID.
- **Suggested direction:** Preserve heading drift without accepting arbitrary documents by requiring topic semantics in either the heading or the table shape (for example, Topic and Gist columns) before a T-row can become a topic. Keep the shared header-only default as an honest zero, but make a contentful foreign table fail by name and retry. Add both the accepted “Discussion themes” case and a rejected Decisions/Tasks table regression.

### 6. Early-exit topic replacement is unprotected by a regression test

- **Location:** `server/meetingminer/pipeline/stages/extract.py:324-359`; `server/tests/test_extraction_topics.py:496-538`; `server/tests/test_worker_extract.py:1105-1168`
- **Severity:** Low
- **Finding:** The implementation correctly deletes old topics before the no-transcript/no-moments return, but no test proves that ordering. The contentful rerun test always retains transcript and moments; the empty-meeting test starts with no topics and asserts only artifacts and extraction sources. A regression that moved `_DELETE_TOPICS` below the early return would leave stale topic navigation while the current suite stayed green.
- **Evidence:** Repository search finds no test that seeds `topic`/`topic_mention`, then enters either early-exit branch. `topics_replaced` is emitted by the early branch but never asserted there. The two existing tests exercise the two halves separately and therefore cannot detect stale rows.
- **Suggested direction:** Add an extract-stage regression that starts with existing topic and mention rows, removes transcript text or moments, reruns the stage, and asserts both tables are empty and `topics_replaced` reports the deletion. Confirm the test fails when deletion occurs after the return.
