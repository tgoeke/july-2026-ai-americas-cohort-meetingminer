## Medium

### No-webcam fallback crops static bottom content

Location: `server/meetingminer/pipeline/frameimage.py:288-321`

`detect_share_region()` calls `_bottom_strip()` even when `_column_boundary()` reports no webcam column. Thus a recording with a bright right edge (the contract's inconclusive layout) and a static bottom band returns `CropRegion(bottom < 1.0, detected=False, method="bottom-strip")` instead of the full-frame inconclusive fallback.

This violates the frozen I/O matrix's **No webcam column** requirement and silently excludes bottom-of-screen evidence from all later change measurements. A static footer, subtitle band, or application status area can then change without contributing to a capture decision. Existing tests cover a uniform no-webcam frame and a bottom strip only with a detected webcam column, so this branch remains green.

The fix must return the configured full-frame inconclusive region as soon as the webcam-column survey is inconclusive, and must add a regression test with a bright right edge, temporal variation above a static bottom band, and assertions for full-frame geometry, `detected is False`, and `method == "inconclusive"`.

## Resolution

Applied after review: `detect_share_region()` now returns the full-frame inconclusive region immediately when the webcam-column survey is inconclusive. `test_no_webcam_column_does_not_crop_a_static_bottom_band` proves that a static footer is retained even when the content above it changes.
