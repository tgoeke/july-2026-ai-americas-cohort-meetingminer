# Epic 6 Context: Bring Any Meeting In

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

A user can add a meeting from the web app — a YouTube URL, a Zoom export, a Teams export, or loose recording/transcript files — and watch it become searchable, citable evidence with live progress. The cohort close-out needs a real, unencumbered corpus, and the owner directed that acquisition be a first-class UI experience with every source option left open and no deadline. Every new source enters through the same write-once source drop and the single `POST /ingests` door; the api only launches acquisition as a separate host process and never downloads, converts, or runs pipeline work itself. Story 6.1 produced the UX design spec that every UI story in epics 6, 7, 8, and 10 adopts.

## Requirements & Constraints

- YouTube acquisition by URL: download a browser-playable MP4 plus captions (English manual preferred, auto-generated fallback, converted to VTT); mint a drop with `sourceId` `youtube:<videoId>`, `corpus` `real`, `startedAt` from release time (second precision) or upload date (day precision), provenance carrying watch URL, channel, duration, yt-dlp version, and format id; then call `POST /ingests`. A repeat run reports `exists` with no media network traffic. Playlists are a command-line feature (one drop and one POST per entry, sequential, per-entry outcome table); no UI story accepts a playlist URL.
- Refuse before writing anything, each refusal named: non-YouTube URL, private/removed video, no video stream, `yt-dlp`/`ffmpeg` missing, duration over a configurable cap (default 180 minutes).
- Add-meeting from the web app: the api validates, launches the tool, answers 202 with an acquisition id; the meeting appears with the existing SSE stage progress once the drop is posted. A pre-submit probe performs the same checks as the tool without downloading, minting, launching, or writing state.
- Uploads require `title`, an RFC 3339 `startedAt` with a numeric UTC offset (collected from the user, never inferred from a date), `corpus: real`, and an explicit transcript dialect whenever a VTT is present. Refused by name for missing metadata, undeclared dialect, unsupported file type, or size over a configured cap.
- Zoom `.vtt` (`Name: text` cue payloads) is converted at acquisition into the trusted speaker-attributed `.txt` format plus a timing `.vtt`; provenance records `transcriptDialect: zoom`. Teams exports pass through unchanged. A dialect is always declared, never inferred from content. The pipeline's transcript contract does not change; Zoom names resolve through the roster exactly as Teams labels do.
- New sources are `corpus: real` and never eval subjects. Acquisition itself makes no paid model calls.
- Extraction prompts describe a "meeting or recorded session transcript", not a Teams meeting; the parser's table headers, item-id prefixes, and timestamp rules are the contract and stay untouched.
- Never guess and no silent fallbacks: every failure surfaces visibly, names the refusing rule, and states the remediation; nothing on screen is invented (counts, reasons, names all come from the api or a human).
- Every designed UI element is backed by a field an endpoint serves today or one a story in this plan creates; a missing field is a finding for the owner, not a placeholder.
- Sequencing: Epic 11 (fast test suite) lands first; 6.2 waits for 11.1 and 11.2 because all three touch `server/tests`. In-epic order 6.1 → 6.2 → 6.4 → 6.5, with 6.3, 6.6, 6.7 alongside; 6.2a extends 6.2, 6.4a extends 6.4, 6.5a extends 6.5.
- Docs land with the code: `docs/README.md` gains YouTube, Zoom, and local-files acquisition sections; the "launch, never run in-process" rule is recorded in `docs/project-record.md` when 6.4 lands.

## Technical Decisions

- One canonical inbox: every source is a write-once drop pinned by the versioned drop JSON Schema. Acquisition tools emit drops and make one HTTP call; they share no code with the pipeline. Intake refuses symlinked canonical files.
- Write-once: assemble in staging, finalize with one atomic rename; an existing target is reported, never written into. "Already produced" is detected by source id, not directory name.
- One live job per source id; a duplicate is a conflict, never a second meeting row. The acquisition surface mirrors this: one running acquisition per source id answers 409.
- No acquisition work in the api process: it launches the tool as a detached host process with a per-acquisition status file and log under `.logs/`. `GET /acquisitions/{id}` reports `queued | running | posted | failed` plus a log tail from that file. `posted` carries `result: created | exists`, the job id and meeting id, and a card-safe `source: {sourceId, tool, toolVersion}`; `failed` carries `refusal: {rule, detail, remediation}` so the client never parses the log tail. The `exists` short-circuit maps to `posted` with `result: exists` and the existing ids.
- Probe and refusal wire shape: `POST /acquisitions/probe {url}` returns `{title, durationMs, captions: {kind, language}, sourceId}` or RFC 9457 Problem Details with stable `rule`, `detail`, and `remediation` fields.
- Uploads stream to a staging directory under the drops root, never into a finalized drop; the api launches the local-file minter with `--transcript-dialect` against staging exactly as it launches the YouTube tool, and removes staging once the drop is finalized or the acquisition fails.
- Reuse the existing local-file minter: the YouTube tool goes through `mint()`'s staging → validate → atomic-rename path via keyword overrides (`source_id`, extra provenance) that default to today's behaviour — no second finalize implementation. `mint-drop` gains `--transcript-dialect zoom|teams-vtt|plain`; the YouTube tool honours `--no-post`, `--drops`, `--api` identically and adds `--playlist` (flat enumeration).
- Every evidence file has a row: the drop carries the per-file sha256/byteSize block the minter already writes; `info.json` is read for metadata, not copied into the drop; the `participants` array is omitted for YouTube drops (omitted means "source did not look").
- Drop contents are read-only after intake, so dialect conversion happens inside the acquisition tool before finalize, never in the pipeline.
- Every threshold is configuration: the duration cap and upload size cap live in the versioned `config.yaml`, not in code.
- Fail closed, fail named, fail before writing: refusals are named errors with non-zero exit; api error bodies are `application/problem+json`.
- New routes register through the auto-discovered route registry; the generated web client is regenerated in 6.4 and 6.4a only.
- Deep links are built client-side with the browser URL API by replacing or inserting the provider's time parameter from the moment's start offset; never concatenate a second time parameter. The existing affordance helper currently offers the deep link only when no recording exists; 6.6 changes it to return both.
- Tests run offline from recorded `info.json` and flat-playlist listings (URL classification, metadata mapping, refusal matrix, `exists` short-circuit, per-entry outcomes); one network test behind an env flag. Web tests cover every Add-meeting tab and failure state, and both deep-link hosts in both replay states.

## UX & Interaction Patterns

- **Adopted design companion.** The versioned spec at `_bmad-output/planning-artifacts/ux-designs/ux-meetingminer-2026-08-29/` — `DESIGN.md` (tokens, color semantics, measured contrast, component visuals) and `EXPERIENCE.md` (information architecture, component behavior, states, interaction primitives, accessibility floor, data traceability, key flows). UI stories 6.5, 6.5a, and 6.6 cite it (tracked path, `updated:` date, adopting commit) and build from the spines' tables first, tracked `mockups/*.html` second; spines win over mocks on conflict. Deviations are recorded in the story spec under a `## Design deviations` heading naming the spine section, the change, and why — an unrecorded deviation is a defect. Token names (`{colors.x}`, `{components.y}`) map to CSS custom properties in `web/src/index.css` or the Tailwind classes that already resolve to them.
- **Idiom: dark only, dense, literal, calm.** The base is the reimagined UI's dark, data-dense look (counts in section headers, offsets as connective tissue, absence stated in place) on a warm dark grey ("Ember & Ink"). Color carries meaning for exactly five things — moment kind, ingestion/acquisition/rerun state, provider/component health, thread identity, ranking reason — each paired with a second carrier (glyph, bar texture, state word, `#name`). Ember is the one brand hue, used only for the primary action and keyboard focus. No decorative color, gradients, illustration, or skeleton cards. State bars keep the existing stage-style values byte-identical; acquisition states reuse them (`posted` renders as done). Every text-on-surface pair is measured (AA minimum); a new pair is measured and added to the contrast table before use.
- **Voice.** Served values in monospace, prose in the sans face; ISO dates, `H:MM:SS` offsets, never relative dates; sentence case, no exclamation marks, no emoji, `api` lower-case; the existing `Cannot reach the api at {API_BASE}: {message}.` sentence verbatim for transport failures, with stale content kept and labeled.
- **Add-meeting is a route (`/add`), not a modal**, reached from the chrome's Add meeting button or the `n` shortcut, laid out as one 720px form column. Source tabs (YouTube URL, Local files, Zoom export, Teams export) are a `role="tablist"`: arrow keys move, a partially filled tab keeps its state, switching never submits. URL tab: a client-side shape check (host and video id) shows a muted hint on failure — not a refusal, nothing was sent; playlist URLs are rejected here with a hint to paste one video's link. After the shape check passes, a 600 ms debounce fires the probe (`Probing…`, Submit disabled); Submit enables only on the current probe's success line (title · duration · captions · source id). Probe, like every async control, uses generation + input-key ownership so a late response never updates newer state.
- **Progress.** An acquisition stepper of state bars with words — launch, running, posted, ingesting (file tabs prepend upload with `<sent> / <total>`) — polls status every 2 s while queued/running, locks the form until posted/failed (no cancel is offered), and shows the log tail as a scrolling mono region (`aria-live="off"`, Copy log, follows only while scrolled to bottom). On posted it subscribes to the job-events stream and renders the existing meeting card in place with the `viewable` Open gate and a `Name speakers` link once transcribe is done on a speaker-less transcript. `exists` reads `Already in the corpus — nothing downloaded.` with the existing card. Lost polling keeps the last state and offers Retry; nothing is inferred.
- **Refusals** render in place as a refusal box (`role="alert"`, rose tint, rule name in mono first, then detail, then `→ remediation` naming the file, key, or process) under the field, under Submit, or under the stepper; sync 409/422 Problem Details go through the existing problem-message helper, a failed acquisition renders the status file's refusal. Dismissed only by changing the input that caused it. Never a toast; never a disabled button without a sentence saying why.
- **File tabs.** A drop zone (drop, paste, or a real file-input trigger; the zone itself is not a keyboard target) produces one file row per file with client-side classification (`recording`, `speaker-bearing .txt`, `.vtt`, `ignored — not a drop file`, kept but never sent); at most one recording and one transcript of each kind, a second replaces the first with a sentence. The dialect select starts on a placeholder, is required on the Zoom and Teams tabs and whenever a `.vtt` is present, blocks Submit with a stated reason until chosen, and shows the content sniff only as a hint beside it, never as the value. Title, started-at (with offset), and corpus `real` are collected before Submit enables.
- **Deep links (UX-DR12).** Replay is primary; the source link is secondary. When a moment's `sourceDeepLink` host is `youtube.com`/`youtu.be`, moment view, drill-down, chat citations, and cards offer `Open on YouTube at H:MM:SS` (outline button, new tab, accessible name includes the offset) beside Replay. Other hosts keep `Open in Stream`; a deep link is the sole affordance only when the meeting has no local replay.
- **Accessibility floor.** WCAG 2.2 AA with keyboard and screen reader; every target ≥ 24 × 24 CSS px; every interactive element a real control with a data-bearing accessible name; Add-meeting focus order is tabs → fields → Submit → stepper bars (`role="img"` named `<step> <state>`) → log tail → meeting card → Open / Name speakers; progress announces politely once per stage transition through one live region per stepper; failures announce assertively via the refusal box. Reduced motion honored; nothing autoplays. At 200% text resize down to 320 CSS px, Add-meeting stays one column with no page-level horizontal scroll.
