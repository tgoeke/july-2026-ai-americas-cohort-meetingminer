### Finding 4 — The lint contract accepts recipes that never enforce lint failures

**Location:** `server/tests/test_lint_contract.py:181`

**Severity:** medium

**Finding:** The contract derives checked paths by discarding every post-`check` token that starts with `-`, and `_tool_commands` only requires `uv`, `ruff`, and `--project` to occur somewhere on the printed line. Consequently, both `ruff check server --exit-zero` and `uv run ... echo ruff check server` satisfy the test. Either mutation makes `make lint` incapable of failing the fast loop while the new contract suite remains green, defeating the regression guard the story says pins the target.

**Evidence:** A read-only mutation probe imported the committed test module, replaced `_dry_run` with each printed recipe, and invoked `test_make_lint_runs_ruff_check_over_the_whole_server_tree()` directly. Its real output was:

```text
exit-zero: ACCEPTED
echo-only: ACCEPTED
```

The first simulated recipe was `cd <root> && uv run --project <server> ruff check <server> --exit-zero`; the second was `cd <root> && uv run --project <server> echo ruff check <server>`. Neither caused an assertion.

**Suggested direction:** Pin the executable argv and post-`check` arguments, including rejecting success-forcing or scope-changing flags, and require `ruff` to be the command executed by `uv run` rather than a token consumed by another executable. Confirm the strengthened test fails against both mutations before accepting it.

**Resolution:** Fixed on the review branch. Permanent mutation cases first reproduced acceptance of both `--exit-zero` and an `echo ruff ...` no-op. The contract now pins the exact argv executed after `uv run --project <server>` to `ruff check <server>`; both mutation cases and the real target are green.

### Finding 5 — The typecheck contract also accepts a no-op command that only mentions mypy

**Location:** `server/tests/test_lint_contract.py:197`

**Severity:** medium

**Finding:** The typecheck assertion checks the working-directory prefix, locates any `-m mypy` pair, and requires only that the final word be `mypy`; it does not require `python` to be the executable run by `uv`. A recipe can therefore replace type checking with `echo python -m mypy`, exit successfully, and keep the contract suite green.

**Evidence:** A read-only mutation probe replaced `_dry_run("typecheck")` with `cd <server> && uv run --project <server> echo python -m mypy` and invoked `test_make_typecheck_runs_mypy_bare_from_server()` directly. Its output was:

```text
echo-only typecheck: ACCEPTED
```

**Suggested direction:** Assert the exact post-`uv run --project <server>` argv is `python -m mypy`, with no intervening executable or additional arguments, and confirm the test fails against the echo-only mutation.

### Finding 7 — The pin contract accepts ranges spanning unmeasured minor versions

**Evidence:** A read-only mutation probe changed the parsed dev dependencies to `ruff>=0.16.5,<1` and `mypy>=2.3.1,<3`, changed ruff `required-version` to `>=0.16.5,<1`, and invoked `test_pyproject_pins_ruff_and_mypy_in_the_dev_group()`. Its output was:


**Suggested direction:** Assert the exact expected bounded ranges (`ruff>=0.16.5,<0.17`, `mypy>=2.3.1,<2.4`) or parse and prove each interval remains within its measured minor. Confirm the test fails against the broad-range mutation.
