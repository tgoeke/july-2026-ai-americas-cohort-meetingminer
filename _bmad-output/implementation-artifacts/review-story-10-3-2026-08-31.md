### F1 — An explicit first ordinal leaves the sequence poised to reuse it

- **Location:** `server/meetingminer/migrations/0017_thread_color_ordinal.sql:63-70`
- **Severity:** High
- **Finding:** The reserve trigger compares an explicit ordinal only with `last_value`. On a fresh sequence, `last_value` is `1` while `is_called` is false, so explicitly importing ordinal `1` does not call `setval`. The next default allocation returns `1` again and fails the unique constraint. This violates the frozen matrix row that accepts an explicit import ordinal and requires later allocation to advance past it.
- **Evidence:** Against an empty private database immediately after migration 0017, `thread_color_ordinal_seq` reported `last_value=1, is_called=false`. Inserting a thread with `color_ordinal=1` succeeded; the next insert omitting the ordinal failed with `UniqueViolation: Key (color_ordinal)=(1) already exists.`
- **Suggested direction:** Make reservation account for both `last_value` and `is_called`, so an explicit value equal to the uncalled sequence start marks that value as consumed before any default insert can receive it. Preserve the ordinary `derive_threads` path: it omits the ordinal and must continue to allocate from the sequence without caller changes.

Status: resolved red-first. The added regression failed on the unfixed migration with the duplicate-key error above. After the reservation comparison was corrected, the regression plus the original ordinal/list suite passed: 15 passed.

### F2 — The two mandated anchors make level transitions disagree at boundaries

- **Location:** `server/meetingminer/api/threads.py:26-33,154-175,205-235`
- **Severity:** High
- **Finding:** Coarse selection and all envelope totals use `topic_mention.anchor_ms`, while the fine rows use and filter on `moment.start_ms`. The two values can straddle any client-supplied window or bucket boundary. A response can therefore report `momentCount: 1` and return no moments, or return a moment while reporting zero mentions/moments. The module's assertion that anchors coincide for every bucket wider than a moment is false whenever a bucket boundary falls between them.
- **Evidence:** For a moment starting at 59 seconds whose mention anchor is 61 seconds, a `[60s,62s]` window includes the mention in `_WINDOW_TOTALS` and the coarse tiers but excludes the row in `_MOMENTS_LEVEL`; `[58s,60s]` produces the inverse. Increasing bucket width does not remove the boundary—placing the same pair around any ladder boundary reproduces the disagreement. The frozen contract simultaneously requires coarse levels to use `anchor_ms`, fine `occurredAt` to derive from `startMs`, and counts to agree across levels.
- **Suggested direction:** Amend the frozen contract to choose one canonical semantic anchor for window membership and level transitions, then re-derive the query and wire requirements from that choice. If fine rows remain moment-anchored, coarse aggregation needs an equivalent moment start without violating the no-`moment` constraint; if mention anchors own membership, the contract must define how a returned moment whose `occurredAt` precedes the requested window is represented. Do not hide the inconsistency by changing only the envelope count.

Status: open; rooted in contradictory frozen-spec requirements and requires an owner decision before remediation.
