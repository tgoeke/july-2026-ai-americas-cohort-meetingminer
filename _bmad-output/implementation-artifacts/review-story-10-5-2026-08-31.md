## Findings

### F1 (high, patch) — nullable `colorOrdinal` from the live parallel API breaks the whole front door

`web/src/features/moments/feed.ts:55,188-197` requires a numeric ordinal, but
Story 10.4 currently serves `colorOrdinal: null` until Story 10.3's migration
lands. A single threaded item therefore throws `FeedContractError` and replaces
all ranked cards with the API-error state. The safe compatibility treatment is
the design's beyond-palette grey: no hue is invented, and the served thread name
still carries identity. Sources: blind-hunter + verification-gap.

### F2 (medium, patch) — the hand-written reader already drifts from Story 10.4 and silently accepts malformed required fields

`web/src/features/moments/feed.ts:46-50,154-248` models reason `at` as a number,
although the Pydantic API serializes it as RFC 3339, accepts unknown reason kinds
and whitespace-only labels, and invents defaults for required `corpus`,
`hasRecording`, `threads`, `total`, `limit`, and `offset`. These failures can
silently render the wrong card or count instead of the reader's promised
page-level contract error. Source: blind-hunter + edge-case-hunter.

### F3 (high, open — frozen contract/API decision) — `Moments 6 of 24` is impossible with the integrated endpoint contract

`web/src/features/moments/MomentsFeed.tsx:170-182` receives only the filtered
response's `total`; Story 10.4 explicitly defines that total as the filtered
set size. Thus six matches render `Moments 6`, and a no-match response renders
`Moments 0`, while the design spine requires `Moments 6 of 24`. The existing
test conceals the mismatch with an impossible filtered fixture (`items: []`,
`total: 24`). Resolving this requires choosing an extra unfiltered-count read,
an API envelope field, or a design amendment. Sources: verification-gap +
acceptance-auditor + blind-hunter.

### F4 (high, patch) — navigation and transient failures discard the kept feed instead of preserving it

`web/src/features/moments/MomentsFeed.tsx:65-116,170-267` re-reads URL filters
while the hidden feed is on a child route, so opening a moment clears the
filter key and reloads the hidden feed. A filter refresh calls `read(0, null)`,
so failure discards prior cards; a failed Show-more loses the original total,
hides paging, and Retry restarts at offset zero. This contradicts the shell's
stated reason for keeping the feed mounted and the stale-card state contract.
Sources: blind-hunter + edge-case-hunter + acceptance-auditor.

### F5 (high, patch) — the card loses served reason/source facts and can keep playing behind navigation

`web/src/features/moments/MomentCard.tsx:109-164,235-241,296-325` replaces a
thread reason's verbatim API label with `threads[].name`, drops refused source
provenance for recording-backed cards, and does not collapse the expanded
player before Open moment/Open meeting navigation. Because the feed stays
mounted, audio can continue behind the destination and Back returns to an
expanded player. Sources: blind-hunter + edge-case-hunter + verification-gap.

### F6 (medium, patch) — several adopted card/contrast rules are defined but not rendered

`web/src/features/moments/MomentCard.tsx:68-90,211-273` leaves screenshots
non-interactive, crops them with `object-cover`, does not clamp excerpts to two
lines, and colors lap-2 thread names with the darker swatch color instead of
the required lap-1 text hue. `MomentsFeed.tsx:291` uses the 10% card border for
a filter control even though the measured `--control-border` token exists
specifically for controls. Sources: blind-hunter + acceptance-auditor.

### F7 (high, patch) — Show-more has neither the required focus transfer nor live announcement

`web/src/features/moments/MomentsFeed.tsx:78-94,236-267` appends the next page
without focusing its first new card title and without announcing `N more
moments — shown of total`. The tests also claim reason order without observing
DOM order and do not exercise late superseded feed responses. Sources:
acceptance-auditor + verification-gap.

### F8 (medium, patch) — empty and failure states omit required actions/announcements

`web/src/features/moments/MomentsFeed.tsx:207-233` invents a visible zero count
before the first response, renders an asynchronous refusal as an ordinary
paragraph, and omits the repeated Add meeting action from the empty-corpus
state. Sources: blind-hunter + edge-case-hunter + acceptance-auditor.

### F9 (high, patch) — inline replay has no captions track

`web/src/features/moments/MomentCard.tsx:232-241` mounts the unchanged
`ReplayPlayer` without the client-generated WebVTT track from meeting
drilldown segments. `EXPERIENCE.md` assigns that accessibility change to Story
10.5 explicitly. Sources: blind-hunter + acceptance-auditor.

### F10 (high, open — owner composition decision) — Search and Ask are outside the sticky chrome

`web/src/App.tsx:187-283` ends the sticky header before Search and Ask and
places both full panels before Moments in `<main>`. They scroll away and the
ranked opening content begins about 310 CSS px down. Moving the existing
panels into a 56px bar requires redesigning `CorpusSearch`/`ChatPanel`, while
Story 8.3 owns the ask surface in this wave; making the current tall panels
sticky would consume much of the 1280×800 viewport. The builder disclosed the
deviation, but it still violates AC3 and the Chrome spine. Source:
acceptance-auditor + blind-hunter.

### F11 (medium, open — integration dependency) — the thread filter is neither complete nor searchable

`web/src/features/moments/MomentsFeed.tsx:152-203` derives options only from
threads carried by currently loaded cards. Threads below the first page cannot
be selected, applying a filter removes other choices, and a deep-linked absent
thread has no matching option. The spine requires a searchable `GET /threads`
source; Story 10.3 now exists on a parallel branch, but its client operation is
not available on this branch and generated-client edits are forbidden here.
Sources: blind-hunter + acceptance-auditor.

### F12 (high, open — conflicting spine order) — moment-card keyboard order is not the specified order

`web/src/features/moments/MomentCard.tsx:211-342` places interactive reason
chips before actions and expanded player controls before the title. The
Accessibility Floor requires title → Replay → Open moment → source → player,
with kind/thread chips after actions, while the visual component description
places the reason line before the excerpt and action row. Correct DOM and
visual order therefore require an owner decision on which ordering wins.
Source: acceptance-auditor.

### F13 (medium, open — frozen design scope) — the Story 10.5 global shortcut surface is absent

`web/src/App.tsx` implements no `/`, `a`, `n`, `g m`, `g t`, or `g e`
shortcuts and no localStorage-backed Settings toggle. `EXPERIENCE.md` assigns
the global keyboard behavior to Story 10.5, but the frozen story AC and builder
handoff do not name this additional Settings work. Source: blind-hunter.

### F14 (medium, patch) — active URL filters can be visually blank while the request remains filtered

`web/src/features/moments/MomentsFeed.tsx:156-203,291-306` does not retain an
active value when it is absent from the currently served option list. A deep
link can therefore send `thread=<id>` while the select shows no selected
value, hiding the active filter from the reader. Source: edge-case-hunter.
