## Post-integration contract correction — 2026-08-31

Story 10.4 landed with `MomentsFeedResponse.corpus_total`, serialized as
`corpusTotal`. The review branch's provisional `unfilteredTotal` name is now a
demo-breaking wire mismatch: the live response cannot satisfy its reader.
This correction is report-first and will be remediated red-first without an
alias or translation layer. The feed transport and public types will consume
the generated `getMomentsFeed` operation and `MomentsFeedResponse`, so a future
server/client rename becomes a compile-time integration failure.

Story 10.3's `listThreads` operation is also generated on main. The local
thread transport seam will collapse onto that operation while retaining the
strict runtime checks that protect the filter from malformed data. Its
timeline contract explicitly allows a returned fine row's `occurredAt` to fall
outside the requested window because mention-anchor time selects membership;
the Story 10.5 surface does not select or position timeline rows.

**Correction result.** `feedCorpusTotalContract.test.ts` served only the exact
landed envelope and failed red because the stale reader demanded
`unfilteredTotal`. The production feed now aliases generated `FeedItem`,
`FeedReason`, `FeedThread`, and `MomentsFeedResponse`, calls generated
`getMomentsFeed`, and strictly validates `corpusTotal`, paging, reasons,
threads, and the required item fields before rendering. No alias, second
request, or derived denominator exists. The thread catalog calls generated
`listThreads` and validates its generated `ThreadsResponse`/`ThreadSummary`
shape before reducing it to select options. The generated operations preserve
RFC 9457 refusal bodies and transport errors for the existing honest UI
states.

**Timeline audit.** Story 10.5 contains no `occurredAt`, window-boundary, or
timeline placement logic: it neither requests nor filters timeline rows. It
therefore cannot impose containment on evidence time; the landed Story 10.3
permission remains intact.

## Findings

### F1 (high, patch) — nullable `colorOrdinal` from the live parallel API breaks the whole front door

`web/src/features/moments/feed.ts:55,188-197` requires a numeric ordinal, but
Story 10.4 currently serves `colorOrdinal: null` until Story 10.3's migration
lands. A single threaded item therefore throws `FeedContractError` and replaces
all ranked cards with the API-error state. The safe compatibility treatment is
the design's beyond-palette grey: no hue is invented, and the served thread name
still carries identity. Sources: blind-hunter + verification-gap.

**Resolved in `ee2d54c`.** `colorOrdinal` is nullable at the wire boundary and
maps to the design's beyond-palette treatment. The new
`feedColorOrdinal.review.test.ts` failed twice before the fix and now passes.

### F2 (medium, patch) — the hand-written reader already drifts from Story 10.4 and silently accepts malformed required fields

`web/src/features/moments/feed.ts:46-50,154-248` models reason `at` as a number,
although the Pydantic API serializes it as RFC 3339, accepts unknown reason kinds
and whitespace-only labels, and invents defaults for required `corpus`,
`hasRecording`, `threads`, `total`, `limit`, and `offset`. These failures can
silently render the wrong card or count instead of the reader's promised
page-level contract error. Source: blind-hunter + edge-case-hunter.

**Resolved in `354f431`.** The reader validates the closed reason vocabulary,
RFC 3339/null `at`, required item fields, and the paging envelope. Nine new
strict-contract cases failed before the fix and now pass.

### F3 (high, resolved; provisional contract superseded) — `Moments 6 of 24` was impossible with the prior endpoint contract

`web/src/features/moments/MomentsFeed.tsx:170-182` receives only the filtered
response's `total`; Story 10.4 explicitly defines that total as the filtered
set size. Thus six matches render `Moments 6`, and a no-match response renders
`Moments 0`, while the design spine requires `Moments 6 of 24`. The existing
test conceals the mismatch with an impossible filtered fixture (`items: []`,
`total: 24`). Sources: verification-gap + acceptance-auditor + blind-hunter.

**Historical provisional remediation in `5fd56ce`/`032f6f3`, superseded by
landed Story 10.4.** The review branch first called the denominator
`unfilteredTotal`; that name and its fixtures are no longer authoritative.
Story 10.4 landed generated `MomentsFeedResponse.corpusTotal`, computed in the
same request from the validated selected corpus before meeting, thread, and
kind filters. The corrected reader enforces
`offset + items.length <= total <= corpusTotal`; when no item filter narrows
the selected corpus, it also enforces `total === corpusTotal`. The header
compares filtered `total` with `corpusTotal`, while Show-more still uses
`total`.

**Former Story 10.4 server obligation — SUPERSEDED AND SATISFIED.** No
`unfilteredTotal` server field is owed. The landed `corpusTotal` field is the
sole denominator contract, is generated into the client, and is consumed
without an alias, a derived count, or a second request.

### F4 (high, patch) — navigation and transient failures discard the kept feed instead of preserving it

`web/src/features/moments/MomentsFeed.tsx:65-116,170-267` re-reads URL filters
while the hidden feed is on a child route, so opening a moment clears the
filter key and reloads the hidden feed. A filter refresh calls `read(0, null)`,
so failure discards prior cards; a failed Show-more loses the original total,
hides paging, and Retry restarts at offset zero. This contradicts the shell's
stated reason for keeping the feed mounted and the stale-card state contract.
Sources: blind-hunter + edge-case-hunter + acceptance-auditor.

**Resolved in `84aba6a`.** Inactive child routes freeze the feed, stale cards
survive filter failures, and Show-more retries preserve the exact offset and
prior rows. Three state regressions failed before the fix and now pass.

### F5 (high, patch) — the card loses served reason/source facts and can keep playing behind navigation

`web/src/features/moments/MomentCard.tsx:109-164,235-241,296-325` replaces a
thread reason's verbatim API label with `threads[].name`, drops refused source
provenance for recording-backed cards, and does not collapse the expanded
player before Open moment/Open meeting navigation. Because the feed stays
mounted, audio can continue behind the destination and Back returns to an
expanded player. Sources: blind-hunter + edge-case-hunter + verification-gap.

**Resolved in `7d128d5`.** Thread-reason labels stay verbatim, refused sources
remain visible as inert provenance, and both navigation actions collapse the
inline player first. Four new fact/ownership cases failed before the fix and
now pass.

### F6 (medium, patch) — several adopted card/contrast rules are defined but not rendered

`web/src/features/moments/MomentCard.tsx:68-90,211-273` leaves screenshots
non-interactive, crops them with `object-cover`, does not clamp excerpts to two
lines, and colors lap-2 thread names with the darker swatch color instead of
the required lap-1 text hue. `MomentsFeed.tsx:291` uses the 10% card border for
a filter control even though the measured `--control-border` token exists
specifically for controls. Sources: blind-hunter + acceptance-auditor.

**Resolved in `aea14e6`.** The screenshot is a non-cropping moment action,
previews clamp at two lines, lap-2 uses the correct text/swatch split, and feed
filters use `--control-border`. Three design-treatment cases failed before the
fix and now pass.

### F7 (high, patch) — Show-more has neither the required focus transfer nor live announcement

`web/src/features/moments/MomentsFeed.tsx:78-94,236-267` appends the next page
without focusing its first new card title and without announcing `N more
moments — shown of total`. The tests also claim reason order without observing
DOM order and do not exercise late superseded feed responses. Sources:
acceptance-auditor + verification-gap.

**Resolved in `36f3416`.** Appended pages focus their first new title and
announce the new count through one polite status region. The same new file

### F8 (medium, patch) — empty and failure states omit required actions/announcements

`web/src/features/moments/MomentsFeed.tsx:207-233` invents a visible zero count
before the first response, renders an asynchronous refusal as an ordinary
paragraph, and omits the repeated Add meeting action from the empty-corpus
state. Sources: blind-hunter + edge-case-hunter + acceptance-auditor.

**Resolved in `dca0080`.** Loading has no fabricated count, read failures use
`role="alert"`, and the unfiltered empty state links to Add meeting. All three
new state cases failed before the fix and now pass.

### F9 (high, patch) — inline replay has no captions track

`web/src/features/moments/MomentCard.tsx:232-241` mounts the unchanged
`ReplayPlayer` without the client-generated WebVTT track from meeting
drilldown segments. `EXPERIENCE.md` assigns that accessibility change to Story
10.5 explicitly. Sources: blind-hunter + acceptance-auditor.

**Resolved in `27d69a8`.** The expanded card reads `/drilldown`, converts its
ordered segments to escaped client-generated WebVTT, and passes the optional
track to the shared player. Captions default off, an explicit Show/Hide control
persists the viewer choice in browser storage, and replay degrades normally if
the transcript read fails. Both new caption cases failed before the fix and
now pass.

**Wave collision narrowed in `b2f85a9`.** Story 7.4 also owns the shared
`ReplayPlayer.tsx`; the final Story 10.5 diff leaves that file byte-for-byte
unchanged and attaches the track from a Moments-local wrapper around it.

### F10 (high, resolved) — Search and Ask were outside the sticky chrome

`web/src/App.tsx:187-283` ends the sticky header before Search and Ask and
places both full panels before Moments in `<main>`. They scroll away and the
ranked opening content begins about 310 CSS px down. Moving the existing
panels into a 56px bar requires redesigning `CorpusSearch`/`ChatPanel`, while
Story 8.3 owns the ask surface in this wave; making the current tall panels
sticky would consume much of the 1280×800 viewport. The builder disclosed the
deviation, but it still violates AC3 and the Chrome spine. Source:
acceptance-auditor + blind-hunter.

**Resolved in `d5b0c10`.** Search and Ask are mounted once inside the sticky
chrome as one-line controls. Focusing one expands its complete results/answer
surface as a bounded overlay without adding flow height; focusing the other
closes the first. Search results, replay, model selection, Ask submission,
streamed answers, and citations remain in the same stateful components.
Navigation collapses the overlay without unmounting either surface. The new
chrome test and re-pointed 17-case B-13 placement pin failed before the change
and now pass.

### F11 (medium, resolved client; Story 10.3 integration required) — the thread filter was neither complete nor searchable

`web/src/features/moments/MomentsFeed.tsx:152-203` derives options only from
threads carried by currently loaded cards. Threads below the first page cannot
be selected, applying a filter removes other choices, and a deep-linked absent
thread has no matching option. The spine requires a searchable `GET /threads`
source; Story 10.3 now exists on a parallel branch, but its client operation is
not available on this branch and generated-client edits are forbidden here.
Sources: blind-hunter + acceptance-auditor.

**Resolved client-side in `c7b2ddc`; concurrent fixtures corrected in
`ba72803`.** A strict Moments-local reader calls `GET /threads` once and
validates Story 10.3's `{threads: [...]}` envelope. A labelled search input
filters a separate ID-valued native select, so duplicate display names cannot
map to the wrong thread. An off-page populated fixture proves that selecting a
searched result writes its `threadId` to the feed URL. A deep-linked ID remains
visible while the catalog loads or is unavailable, and the UI names the
unavailable state; served card threads are never presented as a complete
fallback.

**Remaining until Story 10.3 integrates:** runtime verification against its
populated endpoint, plus replacement or explicit acceptance of this local
reader when generated `listThreads` becomes available. The response consumed
is `GET /threads` →
`{threads:[{threadId,name,mentionCount,meetingCount,firstMentionAt,lastMentionAt,colorOrdinal}]}`.

### F12 (high, resolved) — moment-card keyboard order was not the specified order

`web/src/features/moments/MomentCard.tsx:211-342` places interactive reason
chips before actions and expanded player controls before the title. The
Accessibility Floor requires title → Replay → Open moment → source → player,
with kind/thread chips after actions, while the visual component description
places the reason line before the excerpt and action row. Correct DOM and
visual order therefore require an owner decision on which ordering wins.
Source: acceptance-auditor.

**Resolved in `4bce7bc`.** Per the owner ruling, the interaction spine wins
over the frozen story's visual reason-line ordering. Screenshot and title are
one first moment control, followed by Replay, Open moment, the retained Open
meeting action, source, expanded player controls, then kind/thread chips. The
new exact DOM-order test failed against the prior card and now passes.

### F13 (medium, resolved) — the Story 10.5 global shortcut surface was absent

`web/src/App.tsx` implements no `/`, `a`, `n`, `g m`, `g t`, or `g e`
shortcuts and no localStorage-backed Settings toggle. `EXPERIENCE.md` assigns
the global keyboard behavior to Story 10.5, but the frozen story AC and builder
handoff do not name this additional Settings work. Source: blind-hunter.

**Resolved in `8db9ed1`.** `/` focuses Search, `a` focuses Ask, `n` opens Add,
and `g m`, `g t`, `g e` route to Moments, Threads, and Meetings. The handler
ignores editable controls, modifiers, repeats, and disabled preference state.
Settings exposes the default-on localStorage-backed `Single-key shortcuts`
toggle, with same-tab and storage-event synchronization; Speaker Naming's
scoped `1`/`2`/`3`/`u` bindings honor the same setting. `Esc` remains owned by
the topmost local popover/card. All 41 focused shortcut and Speaker Naming
tests pass.

### F14 (medium, patch) — active URL filters can be visually blank while the request remains filtered

`web/src/features/moments/MomentsFeed.tsx:156-203,291-306` does not retain an
active value when it is absent from the currently served option list. A deep
link can therefore send `thread=<id>` while the select shows no selected
value, hiding the active filter from the reader. Source: edge-case-hunter.

**Resolved in `a754539`.** A current value absent from the observed option list
is retained as a visible option, so copied filtered URLs never render a blank
select. The new deep-link case failed before the fix and now passes.
