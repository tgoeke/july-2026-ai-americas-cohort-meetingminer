# Adoption clause — paste into a story's contract

> **Design companion.** This story adopts the versioned MeetingMiner UX design spec at `_bmad-output/planning-artifacts/ux-designs/ux-meetingminer-2026-08-29/` — `DESIGN.md` (how it looks: tokens, color semantics, measured contrast, component visuals) and `EXPERIENCE.md` (how it works: information architecture, component behavior, states, interaction primitives, semantic zoom, accessibility floor, data traceability, key flows). Build the surfaces this story owns (stories 6.5, 6.5a, 6.6, 7.4, 8.3, 10.2a, 10.5, 10.6, 10.6a — ids per Sprint Change Proposal Addendum 3) from the spines' tables first and the tracked `mockups/*.html` files second; the spines win over every mock on conflict. Deviate only with a recorded reason, written into this story's spec under a `## Design deviations` heading naming the spine section, the change, and why — a deviation without that record is a defect. Every element you render must appear in `EXPERIENCE.md · Data Traceability` with its backing field; an element that needs a field no endpoint serves is a finding for the owner, not a placeholder. `EXPERIENCE.md` refers to `DESIGN.md` tokens by name using the `{path.to.token}` syntax against `DESIGN.md`'s YAML frontmatter — `{colors.kind-decision-text}`, `{components.refusal-box}`, `{spacing.card-gap}` — and the same names are the CSS custom properties you add to `web/src/index.css` (`--color-kind-decision-text`, …) or the Tailwind classes that already resolve to them (`bg-emerald-600` for `{colors.state-done-bar}`). Cite the tracked path, the `updated:` date, and the adopting commit; `.working/`, rendered screenshots, memlogs, and `.snapshots/` are intentionally local evidence rather than the design contract.
