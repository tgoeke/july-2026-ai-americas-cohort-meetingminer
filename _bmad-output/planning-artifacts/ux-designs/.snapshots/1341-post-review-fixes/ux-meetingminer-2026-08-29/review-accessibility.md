# Accessibility Review — MeetingMiner UX spine pair

Reviewed: `DESIGN.md`, `EXPERIENCE.md`, `.memlog.md`, `.working/color-system-a-signal.html` (2026-08-29 drafts). Target stated by the spine: WCAG 2.2 AA, desktop Chrome on macOS ≥ 1280×800, dark only, keyboard + screen reader operable. Method: every ratio below was recomputed from the frontmatter hex/oklch values with an independent script (oklch → sRGB → WCAG 2.x relative luminance); alpha composites were flattened over the surface the screen actually draws them on.

## Overall verdict

The 97-pair contrast table is accurate (every recomputed pair agrees within ±0.03) and the motion, autoplay, live-region, and popover rules are sound. But the spine does not yet meet the AA floor it claims: the focus ring is drawn at 50% alpha (2.60:1, not the quoted 7.44), five composites the screens rely on (queued word and bar, density-alpha buckets, lap-2 names, beyond-palette bands) fall below their thresholds, page-scoped single-key shortcuts fail 2.1.4 (Level A), and reflow/resize (1.4.10, 1.4.4) is explicitly unsupported while AA is claimed. The timeline's keyboard model is real but underspecified in the places that lose focus (tier change, drill, Backspace) and undersized in its targets (ticks, marks, 20px bands). All of it is fixable within the existing token system; the fixes below carry numbers.

## Findings

### Critical

- **[critical]** The focus ring as specified is 2.60:1 against page and card, not the 7.44 the table quotes. `{components.focus-ring}` is "3px `{colors.ring}` at 50%"; the table measures ring at 100%. Composited: ring@50% over `#0A0A0A` = `#2B5680` → **2.60:1** vs page, **2.60:1** vs card (1.4.11 needs ≥ 3:1; 2.4.7). Worse on colored fills: ring@100% vs `thread-9-band` `#4BAEED` = **1.09:1**, vs `thread-10-band` = **1.05:1**, vs `state-running-bar` = **1.25:1**, vs the primary button `#E5E5E5` = **2.12:1**, vs `kind-decision-border` = **1.60:1**. A keyboard user on the Threads canvas cannot see focus on a blue band, which is where the whole semantic-zoom flow happens (DESIGN.md §Colors · Base "ring", §Components · Focus ring; EXPERIENCE.md §Accessibility Floor). *Fix:* draw the ring at 100% alpha (7.43:1 on page) as a two-tone indicator: `outline: 2px solid {colors.ring}; outline-offset: 0` plus a 1px inner offset in `{colors.background}` (background vs ring = 7.43:1) so the ring holds ≥ 3:1 against any fill it sits on, bands included. Change the table row to say "ring as drawn (100%)" and add rows for ring vs thread-9, thread-10, primary. Alternative if the 50% look must stay: alpha ≥ 0.57 is the minimum that reaches 3:1 over page, but that still fails on bands.

- **[critical]** Single-character shortcuts fail WCAG 2.1.4 Character Key Shortcuts (Level A). `/`, `a`, `n`, `g m`, `g t`, `g e` are page-wide; `1 2 3`, `u`, `↑ ↓` on Speaker naming are page-wide (EXPERIENCE.md §Interaction Primitives). 2.1.4 requires one of: a way to turn them off, a way to remap to include a modifier, or "active only when the component has focus". "Never fire inside a text field" is not any of the three. Speech-input users who dictate a word beginning with "n" open Add-meeting; with VoiceOver's single-key Quick Nav on (or NVDA/JAWS browse mode on Windows, where `a`, `n`, `g` are navigation keys) the letters never reach the page, so the documented shortcuts silently do nothing. The timeline keys (`+ − ← → Home Enter Backspace Space o p`) are fine — they are active only while a canvas item has focus. *Fix:* add a Settings toggle "Single-key shortcuts" (default on, persisted in localStorage) that disables `/ a n g-* 1 2 3 u`; state it in §Interaction Primitives and §Accessibility Floor; keep the timeline keys unconditional under the focus exception; scope `↑ ↓` on Speaker naming to the speaker list itself (roving tabindex), not the page.

- **[critical]** Reflow and resize are excluded by the spine's own words while AA is claimed. §Accessibility Floor promises "150% browser zoom at 1280px" (853 CSS px); §Responsive says below 1280 CSS px "is unsupported and only promised to scroll". 1.4.4 Resize Text (AA) requires 200% without loss of content or functionality — at 1280 × 200% = 640 CSS px the 56px chrome holds brand + 6 nav items + Search + Ask + Add meeting + health; nothing says how it fits, so it clips. 1.4.10 Reflow (AA) requires no two-dimensional scrolling at 320 CSS px except for content that needs 2D layout (the timeline is exempt; the Moments grid, Add-meeting form, Speaker naming, and the chrome are not). *Fix:* either (a) specify one narrow layout at ≤ 900 CSS px — chrome wraps to two rows (nav row, then Search/Ask/Add), Moments one column, Speaker naming stacks its three columns, meeting view stacks film strip above transcript above rail — which covers 200% at 1280 and most of 1.4.10, and record 320px as the one deviation; or (b) keep the design and write the deviation into §Accessibility Floor explicitly: "WCAG 2.2 AA except 1.4.4 above 150% and 1.4.10 — desktop-only by owner decision". The honesty rule prefers stating the gap to claiming the level.

### High

- **[high]** Texture is not a working second carrier for the solid states, and the meeting card's stage bars have no per-bar word. DESIGN.md §Colors · States: "A colorblind reader reads the bars from texture alone". Solid covers done, posted, failed, unknown, and running-under-reduced-motion (pulse removed). Recomputed: `state-done-bar` vs `state-failed-bar` = **1.24:1**; `state-running-bar` vs `state-done-bar` = **1.71:1** — a deuteranope reading the eight bars on a meeting card cannot tell a failed `ocr` from a done one (1.4.1 Use of Color). The word is claimed as the third carrier, but the card's eight bars carry stage names, not state words, and §Accessibility Floor makes the bars `aria-hidden` — so a screen-reader user gets no per-stage state either. *Fix:* (1) give failed and unknown a texture as well as a hue — failed: solid with a 2px `{colors.background}` notch at the right end plus a `✕` glyph in `{typography.mono-xs}` after the stage name; unknown: dotted 1px/1px border; running under reduced motion: solid with a 1px lighter top edge; add these to `{components.state-bar}`. (2) Each bar is `role="img" aria-label="<stage> <state>"` (e.g. `ocr failed`), or a visually hidden state word follows each stage name; say so in §Accessibility Floor instead of "bars are aria-hidden".

- **[high]** Five text-on-surface or boundary composites the screens use are missing from the table and fail. Recomputed over the surface each is drawn on (DESIGN.md §Colors · Contrast, `{components.state-word}`, `{components.state-bar}`, `{components.thread-band}`):
  - `state-word.queued` = muted-foreground at 60%: **3.30:1** on card, **3.38:1** on page (text, needs 4.5). *Fix:* queued word at 100% `{colors.muted-foreground}` (6.94/7.66) with the dashed-bar texture carrying "not started"; if a dimmer word is wanted, alpha ≥ 0.76 is the floor on card.
  - `state-bar.queued` = 1px dashed muted-foreground at 40%: **2.11:1** on page, **2.16:1** on card (non-text boundary, needs 3). *Fix:* alpha ≥ 0.55 (3.0:1) — use 60%.
  - `thread-band.fill-beyond` = muted-foreground at 35%: **1.88:1** on page. *Fix:* 55% minimum; 60% recommended.
  - `thread-band.density-alpha` 0.30 and 0.50 steps: thread-1 at 0.30 = **1.64:1**, at 0.50 = **2.62:1** on page. A bucket with real mentions is a graphical object required to understand the band's shape (1.4.11). 0.08 for zero mentions is fine because it means nothing. *Fix:* re-step to `0.08 · 0.55 · 0.70 · 0.85 · 1.00` (every nonzero step ≥ 3:1 for all 12 hues; 0.54–0.56 is the floor across the palette), and keep the numeric tooltip/name as the reading.
  - Lap-2 name as text: `thread-1-band-lap2` `#9C5A6F` on card = **3.50:1**, on page **3.87:1**; thread-12 lap 2 = **3.54:1**. The list column draws the name in "the band color" and the swatch draws lap-2 names in the lap-2 hue. *Fix:* the name is always in the lap-1 hue (`thread-<n>-band`, 6.80 AA on card) with a 12×12 hatched swatch beside it carrying the lap; state that `label-color` is lap-1 for both laps.
  - On-band label over a hatched band: `thread-on-band` `#0B0B0B` over the lap-2 stripe = **3.85:1** and over the 4px gap (page) = **1.01:1**; over a 0.30-alpha bucket = **1.64:1**. *Fix:* labels are never laid over a hatched band or over a bucket below alpha 1.0 — draw the on-band label only at the meetings/moments tiers on the focused thread's full-alpha band, or give the label a `{colors.background}` plate at 70% behind it and measure that pair. Add all six rows to the table.

- **[high]** Timeline focus is lost at every tier change, and the roving model is not buildable as written (EXPERIENCE.md §Interaction Primitives · Keyboard, timeline; §Semantic Zoom; §Accessibility Floor). Gaps a builder must guess: (1) when Ctrl+wheel or `+` crosses a threshold the focused item is unmounted (bands → meetings); the "no layout jump" test is about `x`, not focus — nothing says focus moves to the item at the same `x` in the new tier. (2) `Enter` drills and `Backspace` zooms out one tier — the target item in the new tier is unnamed (the containing meeting? the first moment?). (3) At the bands tier, what is the roving item — the band row (11 items) or the bucket (day buckets over six months × 11 bands ≈ 2,000 focusable elements walked one `→` at a time)? Buckets have accessible names (`retrieval split, 2026-06-08 to 2026-06-14, 14 mentions`), which implies buckets, and `Click or Enter on the band enters the thread`, which implies rows. (4) §Accessibility Floor says the order is "canvas (roving) → evidence card actions" — but an LOD card's Replay/Open moment are inside the canvas; if Tab leaves the canvas, the buttons are unreachable except via `Space`/`o`. (5) The `aria-description` on the canvas (`bands tier, 2026-03-01 to 2026-08-29`) is on the container, which is never focused under roving tabindex, so no screen reader ever reads it. *Fix:* specify the canvas as `role="grid"` with `aria-label="Threads timeline"` and `aria-rowcount`; rows are threads (row header = `#name`), cells are the tier's items; `↑ ↓` rows, `← →` cells, matching the spec exactly. Roving focus: on entry, the cell nearest the window center on the focused/first thread; on any tier change (wheel, keys, Enter, Backspace, double-click) focus moves to the cell in the new tier whose span contains the previous cell's `x` (Enter: the first child; Backspace: the parent). Inside an LOD card, Tab moves through Replay → Open moment → Open on YouTube, then leaves the grid. Put the tier and window in the grid's `aria-label`/`aria-roledescription` update and in the existing polite region (already announced once per tier change) and drop `aria-description`. At the bands tier the cell is the bucket, but `← →` skips zero-mention buckets and `Shift+← →` pans; state the per-tier cell in the tier table's "What is drawn" column.

- **[high]** No text alternative rule for screenshots and no captions for the inline player (1.1.1 and 1.2.2 are Level A). Every Moments card, LOD card, and film-strip frame is an `<img>`; nothing in either spine says what its `alt` is (DESIGN.md §Components · Moment card, LOD card; EXPERIENCE.md §Data Traceability · Moments "Screenshot"). The inline player replays synchronized media; the product owns a transcript for every meeting, yet the player is specified with no `<track>`; on the Moments card the only text is a two-line excerpt. *Fix:* add a traceability row "Screenshot alt = `<viewType> at <offset>, <meetingTitle>`" (`DrilldownScreenshot.viewType` is `slide | ui-screen | participant-gallery`, existing) and, where OCR text exists for the frame, append its first line. Add a row for the player: `ReplayPlayer` attaches the meeting's transcript segments as a WebVTT `<track kind="captions">` generated client-side from `/drilldown` `segments[]` (existing data); default off, remembered per viewer. Record it as a story 10.5/10.6 web change in `findings-for-epics.md` if the player is out of the spine's reach.

- **[high]** Timeline targets are below 24×24 CSS px and overlap (2.5.8 Target Size Minimum, AA). Moments tier draws "moments as ticks at `startMs`" — a tick is 1–2px wide; two moments 30 s apart at 4 min/px are 0.125px apart, so targets overlap entirely and the spacing exception cannot apply. Meetings tier draws marks "whose width is their duration": a one-hour meeting spans 0.5px at 2 h/px and 15px at 4 min/px. Bands are `{spacing.band-height}` 20px with `{spacing.band-gap}` 4px — a 24px circle on each band is exactly tangent to the neighbor's, the boundary case. At the meetings tier "other threads' bands collapse to 4px strips"; if a strip is clickable to enter that thread it is a 4px target beside other 4px targets. Buckets are "≥ 8px wide". (EXPERIENCE.md §Semantic Zoom tier table; DESIGN.md `spacing.band-height`.) *Fix:* every timeline item gets a hit area of at least 24×24 centered on its drawn geometry (`min-width: 24px` on the interactive element, drawn tick inside it); when two items' hit areas would overlap at the current scale they are clustered into one item named `3 moments, 12:40–12:52` that drills on Enter/double-click (this also caps screen-reader verbosity); set `band-height` to 24px (or keep 20 and raise `band-gap` to 6px); collapsed 4px strips are not targets — the list column is the way to switch threads at that tier — and say so.

### Medium

- **[medium]** Control boundaries fail 1.4.11 on the achromatic base. Recomputed: `{colors.border}` white@10% over page = **1.25:1**; `{colors.input}` white@15% over page = **1.47:1**, over card **1.57:1**; hover border white@20% = **1.77:1**; a card-colored field on the page = **1.10:1**. Inputs (Search, Ask textarea, URL field, name field, Title/Date), the model-select trigger (`1px solid {colors.border}`), and shadcn `outline` buttons (Open moment, Copy log, Clear filters, clip buttons) are all identified only by that border. The shadcn defaults inherited this; the spine restates them as the design (DESIGN.md §Colors · Base "border", `{components.model-select.trigger-border}`, `{components.chrome}` "each a card field with border"). *Fix:* add one token `control-border: '#FFFFFF57'` (white at 34%, **3.0:1** on page; 33% suffices on card) used for inputs, select triggers, and outline buttons; keep `{colors.border}` at 10% for cards and gridlines, which are not controls. Add the row to the table.

- **[medium]** Refusal boxes outside the stepper are never announced. §Accessibility Floor gives a live region to steppers and cards only; the refusal boxes for sync 409/422 under Submit, the name-field PUT refusal (Flow 3 failure), the Settings 422, and the tier-fetch refusal under the canvas have no region, so a screen-reader user who pressed Enter hears nothing (4.1.3 Status Messages). *Fix:* `{components.refusal-box}` is `role="alert"` (assertive, matches "failures announce assertively") with the rule name first in DOM; it is inserted into the DOM on appearance rather than unhidden, and the trigger keeps focus. State it once in §Component Patterns · Refusal box so each surface inherits it.

- **[medium]** Dragging and pointer-only zoom have no non-drag pointer alternative (2.5.7 Dragging Movements, AA). Pan is drag, wheel, or keyboard; zoom out is Ctrl/⌘+wheel or keyboard only; double-click zooms in only. Wheel and keyboard are not "single pointer" operations. Nothing on the canvas shows a pointer user that `+ − Home` exist. *Fix:* a small control cluster on the canvas edge — `−` `+` `Fit` `‹` `›` as outline buttons with their key names in the accessible name (`Zoom in (+)`) — which also makes the shortcuts discoverable. Add to §Component Patterns · Timeline canvas and to §Data Traceability (client).

- **[medium]** Kind glyphs are underspecified for a builder and noisy for a screen reader. `◆ § ☐ ▣ ≡ ✕ Δ` are Unicode characters set in Geist Variable at 12px; Geist does not cover U+2610 `☐`, U+25A3 `▣`, or U+25C6 `◆`, so Chrome substitutes a fallback face per glyph with different sizes and baselines, and `☐` vs `▣` (empty square vs filled square) differ by an inner fill of about 4px at 12px. Read aloud they are "black diamond suit decision", "ballot box action item". The spine is right that the glyph is the second carrier; it must be reliable (DESIGN.md §Colors · Moment kinds, `{components.kind-chip.glyph}`). *Fix:* ship the seven glyphs as 12×12 inline SVGs (one sprite) drawn at 1.5px stroke, `aria-hidden="true"`, with the kind name as the chip's text; swap `☐/▣` for a more separable pair (e.g. a checkbox outline vs a bookmark). Also hide the `#` prefix and `→`/`·` separators from the accessible name (`aria-hidden` spans) and name thread chips `thread retrieval split`.

- **[medium]** Expanded-card focus and toggle semantics are unstated. Replay "toggles the inline player… `Esc` collapses the expanded card"; if focus is inside the player when Esc fires, the player unmounts and focus drops to `body`; opening a second card collapses the first likewise (EXPERIENCE.md §Component Patterns · Moment card; §Accessibility Floor). *Fix:* Replay carries `aria-expanded`; on collapse (Esc, another Replay, or Open moment) focus returns to that card's Replay button; on expand, focus stays on Replay and the player is next in Tab order (already the order given).

- **[medium]** Kind chip as a filter toggle has no pressed state and no non-color pressed carrier; chips are 23.4px tall. `{components.kind-chip}` is fill + text + border in every state; "in a filter row it is a toggle" (EXPERIENCE.md §Component Patterns · Kind chip). Height = 12px × 1.45 + 2×2px padding + 2×1px border ≈ 23.4px, under 24 — it passes 2.5.8 only via the spacing exception (6px gaps). *Fix:* `aria-pressed`; pressed = fill, unpressed = transparent fill with the kind border (the same fill/outline distinction the thread chip already uses); `chip-padding: 3px 8px` so chips are ≥ 24px tall and the exception is not needed. Same padding for thread chips; give the chrome health button `min-height: 24px`.

- **[medium]** The log tail is auto-updating, scrolling content with no pause (2.2.2 Pause, Stop, Hide). "Scrolling mono region, newest line last" for the length of a download; a reader who scrolls up to read a line is scrolled back on the next line (EXPERIENCE.md §Component Patterns · Acquisition stepper). *Fix:* auto-scroll only while the region is scrolled to its bottom (pin-to-bottom); any upward scroll pauses following until the user returns to the bottom; state it. The 2s running pulse is under 3 flashes/s (2.3.1 ok) and stops under reduced motion; leave it.

- **[medium]** Speaker-naming keys collide and Enter has two meanings. `↑ ↓` select tags page-wide, but inside the combobox `↑ ↓` walk suggestions; "Enter with a highlighted suggestion picks it, Enter with none submits the typed text as a new name" and separately "`Enter` in the name field submits" and "**Save** sends one PUT per tag" (EXPERIENCE.md §Component Patterns · Name field; §Interaction Primitives). *Fix:* the speaker list is a `listbox`/roving group; `↑ ↓` act only while a row has focus. In the combobox: first Enter on a highlighted option selects it and closes the list (`aria-autocomplete="list"`, `aria-activedescendant`); Enter with the list closed submits the assignment (same as Save). `u` and `1 2 3` are covered by the shortcuts toggle above.

- **[medium]** Model select roles and names are unspecified. "Arrow keys move, Enter selects, Esc closes" fits a single-select `listbox` with `role="group"` per provider (or a `radiogroup`); either is fine, but the spine must say which, and: the trigger's accessible name must include the health word (`chat, claude-sonnet-5, anthropic, ok`); the `●` is `aria-hidden`; a muted invalid/missing option is **not** `aria-disabled` (it is selectable by design) and carries its remediation as `aria-description`; ✓ is `aria-selected`, not a character (EXPERIENCE.md §Component Patterns · Model select; DESIGN.md `{components.model-select}`). *Fix:* add those five sentences to the Model select row.

- **[medium]** The thread-hue rule is not implementable as two of its statements conflict, and hue is the primary identity carrier on the canvas. "Assigned client-side from `FNV-1a(threadId) mod 12`" yields 0–11 for every thread; "threads 13–24 take the same hue at lap 2" and "past 24 the band is muted" require an ordinal. A hash cannot know a thread is the 13th (DESIGN.md §Colors · Threads; EXPERIENCE.md §Data Traceability · Threads "Thread hue"). *Fix:* decide one: (a) ordinal by first-mention date (stable, sortable, laps well-defined) — recommended, since the design already accepts hue collisions; or (b) hash for hue and lap = number of earlier-created threads that share the hue (deterministic given the list). Also state whether density quintiles are per thread or across all visible bands.

### Low

- **[low]** `+` needs `=` as an alias (on US layouts `+` is Shift+=), and `−` should accept both `-` and numpad minus; say so in §Interaction Primitives.
- **[low]** `Show 24 more`: after the append, move focus to the first new card's title and announce `24 more moments — 48 of 96` in the Moments header region; otherwise a keyboard user is left on a button that moved.
- **[low]** Bucket tooltip appears on hover only; make it appear on focus too (it is the cell's name, so the SR path is fine; sighted keyboard users still need it).
- **[low]** `{typography.label}` at 10px with 0.1em tracking (`machine-derived`, stat labels) is 6.94:1 on card, so it passes, but 10px on a 1280-wide desktop at 100% is at the edge of legibility; 11px would cost nothing.
- **[low]** One live region per meeting card means N regions when several ingestions run at once; acceptable for one operator, but a single polite region per list ("Meeting X: transcribe running") is simpler and never interleaves.
- **[low]** Moment card: the screenshot and the title both open the moment view — two links with the same target; name the image link by the card title or wrap both in one link so a link list reads once.
- **[low]** Offset chip text must stay `{colors.foreground}`: worst case (white screenshot behind `rgba(0,0,0,.6)`) is **5.50:1**; `{colors.muted-foreground}` there would be **2.22:1**. Add a Don't row.
- **[low]** `chrome` health control: 8px dot + 12px word is ~17px tall; the spacing exception covers it in a 56px bar, but `min-height: 24px` removes the dependency.

## Verified

- **Table pairs recomputed from the frontmatter values (mine / spine):** foreground/background 18.97 / 18.96; foreground/card 17.18 / 17.16; muted-foreground/background 7.66 / 7.63; muted-foreground/card 6.94 / 6.91; primary-foreground/primary 14.23 / 14.22; ring/background at 100% 7.43 / 7.44; kind-decision-text/fill 9.55 / 9.57; kind-decision-as-text/card 11.81 / 11.77; kind-decision-border/card 4.19 / 4.21; kind-bug-fix-border/card 3.96 / 3.96; state-failed-bar/background 4.37 / 4.39; state-failed-text/card 6.26 / 6.26; state-unknown-bar/background 4.25 / 4.25; health-invalid-dot/card 3.96 / 3.97; thread-1-band/background 7.51 / 7.50; thread-1-on-band/thread-1-band 7.47 / 7.45; thread-1 as text/card 6.80 / 6.79; thread-1-lap2/background 3.87 / 3.88. Differences are hex rounding; the table is honest. The oklch→hex renderings spot-checked (ring, background, muted-foreground, thread-1, thread-1-lap2, state-failed-bar, kind-decision text and fill, thread-9) all reproduce exactly.
- **Missing pairs that pass (add them to the table):** state words on the page background (Add-meeting stepper, Speaker-naming header): failed 6.92 AA, unknown 7.64 AAA, running 11.49 AAA, posted 10.21 AAA, not-required 7.53 AAA. Refusal box on the rose 12% tint (composite `#31141C` on card, `#250910` on page): detail foreground 16.14 / 17.88 AAA; rule `state-failed-text` 5.89 / 6.52 AA; remediation muted-foreground 6.52 AA / 7.22 AAA. Log tail muted-foreground over `muted` at 40% on card 6.52 AA (foreground 16.15). Offset chip foreground over `rgba(0,0,0,.6)` on a white screenshot 5.50 AA. Skipped bar 1px border at 60% on card 3.26 (non-text). Cursor line foreground at 40% 3.66 (non-text). Lap-2 band on a card surface 3.50 (non-text). Destructive on background 6.85 AA. No text is specified over the running amber bar (words are beside bars); if a builder ever puts text on it, `thread-on-band` reads 9.22 and foreground 2.05.
- **Hatch legibility:** lap-2 hatch 135° 3px/7px shows two full periods in a 20px band — visible; skipped-bar hatch 2px/5px runs diagonally along a 6px bar and reads as a stripe, not a fill — visible; dashed 1px queued outline at 6px reads as dashed. The texture set works everywhere except the solid group (finding above).
- **Motion and time:** `prefers-reduced-motion` coverage is complete for what the spine draws — zoom easing, tier cross-fade, running pulse, tier-fetch progress line, pan inertia; hover is a border change with no transition. No autoplay anywhere (player starts on Replay, Space, or a clip button); the 8-second clip stop is user-initiated playback that pauses, not a time limit. 2s polling, the 8s search timeout, and the 60s chat timeout are request timeouts, not limits on user activity — 2.2.1 does not apply, and the chat `timeout` failure already renders in place with the previous answer kept. The 2s pulse is 0.5 Hz, far under 2.3.1's three flashes per second.
- **Screen reader:** the chat answer region's `aria-live="polite" aria-busy` defers announcement of streaming tokens until the answer completes — correct; the log tail is `aria-live="off"` — correct; tier changes announce once and continuous zoom does not — correct frequency; stage transitions announce once per transition, failures assertively — correct politeness split. Accessible names include their data (`Replay recording at 12:40`, `Play clip 2 of SPEAKER_03 at 41:07`). Popovers trap nothing, Esc closes, focus returns to the trigger. Source tabs are `role="tablist"` with arrow-key automatic activation; Base UI Tabs supplies `tabpanel`/`aria-controls`. The name field's list-autocomplete behavior (suggestions highlighted, never filled) is the WAI-ARIA combobox pattern. The timeline is DOM-rendered, not `<canvas>` — the right decision for naming and focus.
- **Keyboard:** global shortcuts are guarded inside text fields; `Esc` has one meaning per layer (topmost popover, then expanded card); timeline keys are scoped to canvas focus; `Backspace` is safe in Chrome (no history navigation). Focus order per screen is DOM order except the meeting view's existing rail. Popover focus return is stated.
- **Target size:** `Show 24 more`, Replay, Open moment, Rename/Merge, Save, Copy log, Clear filters, Retry (shadcn `Button` default h-9 = 36px, sm h-8 = 32px); source tabs (8px + 21px + 8px = 37px); speaker rows (full-width buttons); clip buttons (outline, mono-sm, ≥ 32px); 6px state bars and 8px health dots inside the status page are non-interactive and need no target. Citations inside chat prose fall under the inline exception.
- **Non-color carriers present and perceivable:** kind = glyph + name (with the font caveat above); health = dot + word + remediation, and the chrome dot's word is the existing `summarize()` label; thread = `#name` always rendered in the list column; ranking reason = the api's verbatim label; queued/skipped states carry dashed/hatched textures that read at 6px.
