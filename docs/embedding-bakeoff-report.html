Retrieval evaluation · S2P meeting archive

Which embedding model should search our meetings?

Nine configurations of eight models, measured on 303 labelled retrieval tasks drawn from our own 7,730-passage transcript archive — and one baseline that uses no embeddings at all.

August 18, 2026 Corpus 7,730 passages · 167 meetings Queries 183 cited claims + 120 generated questions Hardware local Ollama host, no external services
Recommendation

Switch to snowflake-arctic-embed2. The re-index costs minutes.

On questions phrased the way people actually ask them, snowflake-arctic-embed2 retrieves the right passage in the top five 60.0% of the time against 43.3% for the model in production — an MRR gain of 0.130, the largest effect in this study. It costs 26.9 passages/second against 49.7, so re-indexing the whole archive takes about 5 minutes and adds 33% to vector storage on a store measured in hundreds of megabytes. That is a real improvement at negligible cost — but note it appears almost entirely on paraphrased questions, and barely at all when queries reuse the transcript's own words.

Method

How the models were judged

The hard part of a retrieval evaluation is the answer key. Rather than hand-write one — which tends to reward whatever the author already believes — both query sets were derived from artefacts the archive already produces.

Query set 1 · 183 tasks

Cited claims

Every decision, action and risk our summariser extracts carries a [m:ss] citation into the transcript. Each becomes a query whose correct answer is the passage it cites. Real analyst language, but it borrows the transcript's own words — which flatters keyword search.

Query set 2 · 120 tasks

Natural questions

A local model was shown individual passages and asked for a question a colleague might ask weeks later, explicitly avoiding the passage's distinctive words. Low word overlap by construction — which flatters semantic search.

The two sets are biased in opposite directions on purpose. A configuration that wins both is a safe choice; one that wins only its favourable set is not.

Protocol

  1. Screen. All nine configurations against a 2,000-passage pool, to eliminate the clearly uncompetitive before spending hours of GPU time.
  2. Full run. Every configuration re-measured against the complete 7,730-passage archive — the same haystack the live system searches, since recall depends on how much there is to get wrong.
  3. Score. Each query ranked against every passage by cosine similarity, then the same measurement repeated for the hybrid the live system runs: keyword and vector results merged by reciprocal-rank fusion.

What was measured, and why

  • Recall@5 — was the right passage in the top five? This is the operational number: five passages is roughly what fits in an answer's evidence window.
  • MRR@10 — how high did the right passage rank? Rewards putting the answer first, not merely somewhere on the page. Used as the primary ranking metric.
  • Hybrid vs text-only (Δ) — what the embeddings add on top of keyword search. This, not the vector score in isolation, is what a model must justify.
  • Throughput and index time — a two-point gain that quadruples indexing time is not a win on a shared host that also serves summarisation.
  • Strict vs adjacent credit — passages overlap by one speaker turn, so a neighbour often contains the same statement. Every metric was computed both ways; strict figures are reported here, and the gap between them is a property of the passage boundaries, not of any model.

Reading the result

What this changes

  • Change the embedding model to snowflake-arctic-embed2 and re-index. Minutes of compute for the single largest retrieval gain measured here.
  • The documented prompts stay off. They measured worse on both query sets. Worth re-testing if the passage format changes, since prompting interacts with content shape.
  • Keep the hybrid, and keep investing in keyword search — synonyms for our vocabulary (SFTP/FTP, PO/purchase order) and field boosts. It is the stronger half whenever a query borrows the transcript's words, which is most of how the archive is searched today.
  • Passage boundaries are the bigger lever. The gap between strict and adjacent scoring says a meaningful share of "misses" are the answer sitting one passage over.
Limitations

What this evaluation does not establish

  • The answer key is machine-derived. Citation timestamps are mapped to passages by a rule, and the questions were written by the same family of model that writes our summaries. Neither is a human relevance judgement.
  • One corpus, one domain, one language. These results describe procurement-programme meetings at this organisation, not embedding models in general.
  • Single run per configuration; no confidence intervals. Differences below roughly 0.03 MRR should be treated as indistinguishable.
  • Passage size and overlap were held fixed. They are plausibly a larger lever than model choice and were not varied here.
  • Answer quality was not measured — only whether the right passage was retrieved. Retrieval is necessary for a good answer, not sufficient.
